# 证据卡到主题的闭环工作流 V1.0（历史版）

> 当前执行入口已升级为[AI辅助水利文献发现到深度主题形成工作流](03_AI辅助水利文献发现到深度主题形成工作流_讨论稿.md)。新流程在全文与Claim准入之前增加“初步主题—人工筛选—既定主题”硬门，并拆开主题层、文献层和证据卡补核层的优先级。本文件只解释旧版十二步流程，旧命令和模板不再用于新建主题。

## 1. 这套Skill真正产出什么

第二个Skill是 [`hydrology-theme-synthesis`](https://github.com/iHeadWater/mylibrary/blob/main/skills/hydrology-theme-synthesis/SKILL.md)。它接在证据卡Skill后面，生成一份主题档案，而不是自动吐出一个主题名。

主题档案包含：主题问题与边界、输入快照、比较框架、主题声明、发展脉络、文献排序、原卡反馈、重算记录、写作接口以及人工和导师决定。完整模板见[水利科研主题模板 V1.0](../主题模板/01_水利科研主题模板_V1.0.md)。

## 2. 使用前准备

能支撑主题结论的Claim必须同时满足：

- 证据卡为L2或L3；
- `verification_status`为`source_checked`或`independently_reproduced`；
- Claim出现在原卡`verified_claim_ids`；
- 有明确定位、范围、支持与不支持边界；
- 能直接回答当前主题问题。

L0/L1、只读摘要、机器转述和未核数字可以帮助找文献，但不能承重。

## 3. 十二步执行

### 01 写清问题和用途

写一个可回答的问题，并说明是为研究现状、综述、活跃问题还是项目判断服务。没有具体问题就先停在证据卡检索。

### 02 查现有主题

搜索核心问题、同义词、上位方向和相邻主题。能进入已有主题时优先形成增量；不能因新方法、新地区或页面长就新建主题。

### 03 冻结输入快照

~~~text
python skills/hydrology-theme-synthesis/scripts/build_theme.py --theme-ref draft:主题短名 --title "候选主题名" --question "具体科研问题" --intended-use "本轮用途" --card 文献/卡1.md --card 文献/卡2.md --output 主题/候选主题.md
~~~

首次不加`--include-all-verified`。先查看`candidate_verified_claim_ids`，读过原卡后用`--claim CLAIM-ID`明确纳入。脚本不分配正式主题ID。

### 04 做Claim准入

每条Claim选择included、context_only、excluded或feedback_needed并写原因。排除常见原因包括不相关、不可比、同源重复、版本取代、L级不足或需补核。

### 05 建比较框架

对齐对象、地区、时期、事件、方法、信息集、基线、指标、分母、验证设计和目标场景。关键口径一致仍相反才算真冲突。

### 06 形成主题声明

每条TS-xx只写一个命题，列出支持、限制和相反Claim，给六维证据画像，写最强允许结论与不能支持内容。无已核Claim时写unknown或insufficient。

### 07 梳理发展脉络

按问题、数据、方法、验证和适用范围的变化梳理，不能按年份罗列标题替代科学脉络。趋势必须有Claim支持。

### 08 排关键文献

先判断科学作用，再填写E/D/G/R/V。新近性25%、期刊信号15%，合计40%，提高近期高影响论文的前沿关注优先级。期刊信号只使用有出处的JIF学科百分位或分区；高分表示先读先核，不表示更可信。旧奠基论文、长期监测、标准、报告、数据和软件按实际作用保留。

### 09 由主题反推原卡

主题出现承重缺口时建立EFR请求，说明原卡、Claim、问题、最小材料、可能改变什么和停止条件。只有“有明确判断＋缺口可定位＋新材料可能改变判断”三门同时满足才补核。

### 10 补核后重算

修改原卡，运行证据卡校验，再更新主题快照、综合声明和优先级。请求未核时只能保持proposed。

### 11 准备Idea和写作接口

列出哪些TS/Claim可用于背景、研究现状、趋势、问题、方法和局限。机会只记录为signal，写最近工作、具体差异、新颖性检索缺口、反证和可行性条件，不能从“当前没看到”推断“无人研究”。

### 12 人审、导师决定、校验和同步

~~~text
python skills/hydrology-theme-synthesis/scripts/validate_theme.py 主题/候选主题.md --mode draft --index-root .
python skills/hydrology-theme-synthesis/scripts/validate_theme.py 主题/候选主题.md --mode final --index-root .
~~~

人工逐条核对承重原文定位和指标来源；导师决定并入、保持候选、建立观察、激活、退回或停止。通过后检查Git差异，经当前分支、PR和Issue交付。

## 4. TG01—TG10硬规则

| 规则 | 核心检查 |
| --- | --- |
| TG01 准入 | 只引用真实存在的L2/L3、source-checked Claim |
| TG02 问题与边界 | 有具体问题、三类依据、纳入排除、相邻主题比较 |
| TG03 可比综合 | 综合声明有Claim，真冲突有一致比较框架 |
| TG04 去重与谱系 | Claim、来源版本、独立性组和版本家族不重复计数 |
| TG05 指标边界 | 科学作用与关注分分开，JIF不冒充证据质量 |
| TG06 公式可复算 | 权重、R/V映射、缺失区间和重归一可重算 |
| TG07 反馈触发 | 请求指回原卡/Claim并通过三门 |
| TG08 写回闭环 | applied有原卡前后版本、改动Claim和重算结果 |
| TG09 人机权限 | AI、人审、导师和生命周期状态分开 |
| TG10 写作边界 | opportunity保持signal，空白与新颖性不混同 |

PASS只表示结构门通过，不证明主题科学正确。

## 5. 排序例子

假设当前为2026年：

- 2025年、JIF学科百分位95、E=3、D=4、G=4的论文：R=4、V=4，关注分93.75，应优先检查。
- 1998年的奠基论文：R=0，但可标记foundational exception；承担定义或核心方法时仍进入承重阅读集。
- 最新政府调查报告：V为not_applicable，其他适用权重重归一；不能因无JIF降低其监测事实作用。
- JIF来源不明：V为unknown，输出分数区间和完整度，不能填0或猜数。

## 6. 主题反馈不是把卡写长

只在会改变核心判断、真冲突裁决、因果／预测／迁移含义、重复计数、后续Idea前提或写作承重点时补原卡。只增加字数而不改变判断、边界或下一步的信息不触发。

## 7. 完成标准

完成后，另一个人应能回答：主题研究什么；边界在哪；认识依据和强度；哪些是真冲突；哪些文献承重、哪些优先跟踪；原卡要补什么；补核后哪里改变；哪些内容可用于写作；哪些环节由AI、人和导师分别负责。
