# 证据卡分类与填写说明 V0.4

本轮产品候选规范，2026-09-03。分类用于选择填写模块，不是证据质量排名，也不因文献类型改变既有正式内容权限。所有字段均填写实际取得、实际读到的内容；没有材料时只保留模板，不能示范编造研究结果。

> 2026-09-04执行入口：V1.2 将八类来源类型、证据角色和方法模块分开，并配套 Zotero 只读 Skill。请从[证据卡科学架构与 Zotero Skill 使用 V1.2](07_证据卡科学架构与Zotero_Skill使用_V1.2.md)进入；本文件只保留分类形成过程。

## 先分清两个维度

**材料类型**决定主要填什么；**证据角色**决定能支持什么。一份政府发布的技术报告可能同时包含统计数据、模型试验和建议；应选一个主要材料类型，再标明每条声明的角色。不是“官方报告”就比研究论文更能证明因果，也不是发表过就已独立验证。

| 主要类型 | 什么时候选 | 下一步主要用途 |
| --- | --- | --- |
| 1. 原创研究 | 实验、观测、模型、理论推导、定性或混合研究 | 比较方法、结果及其适用条件 |
| 2. 综述与证据综合 | 叙述综述、系统综述、范围综述、Meta分析 | 梳理研究版图、分歧和证据缺口 |
| 3. 调查、监测与统计报告 | 普查、政府调查、监测通报、统计年鉴 | 确认现实规模、时空分布、观测与统计口径 |
| 4. 工程项目报告 | 设计、可研、运行、评估、灾后调查中的工程分析 | 提取场景约束、工程措施与实施效果证据 |
| 5. 图书与章节 | 专著、教材、手册、章节 | 定义概念、追踪理论和方法来源 |
| 6. 标准、指南与政策 | 技术标准、操作指南、管理文件 | 确认规范要求、适用范围和约束 |
| 7. 数据集及数据说明 | 数据产品、数据论文、元数据与质量报告 | 判断数据是否适合某个研究问题 |
| 8. 软件、模型与代码 | 代码仓库、模型手册、软件论文、版本发布 | 判断实现范围和复现资源是否满足要求 |

学位论文、会议论文、预印本首先按研究内容选模块，同时记录发布形式与审查状态。新闻、演讲、网页简介等不能硬塞成研究结果：可作为线索或背景，记录来源并追到原始材料。复合材料在同一张卡里增加相关模块；同一报告的一张表和正文引用不是独立证据。

## 所有类型共用的部分：直接复制后填写

原论文八部分模板继续用于研究论文。本节为其他来源的共同部分，可作为同一来源页的结构，不要求所有非论文来源新建正式卡。已有来源条目或主题中的完整记录时，继续更新原位置。

```markdown
# 〔实际来源名称〕

## 来源身份与本轮使用目的
- 题名、作者/机构、出版者或发布方：
- 年份、发布日期、版本/版次、报告号/DOI/ISBN/数据版本/代码版本：
- 官方来源链接：
- Zotero条目或文献目录入口：
- 来源类型、发布形式、是否知道其审查状态：
- 本次用于回答的问题：
- 与其他版本、报告、论文、数据集的关系：

## 材料与阅读范围
- 实际取得的材料：
- 实际读过的页、章、图表或条款：
- 尚未取得或尚未阅读：
- 获取日期、所用版本；更新/勘误/撤稿状态及核对范围：

## 内容与证据
〔在这里插入下文所选类型模块；先写材料内容，再写本方理解。〕

## 逐条声明与原文定位
| 声明编号 | 原文事实或忠实释义 | 证据角色 | 对象与条件 | 数值/单位/不确定性（适用时） | 具体位置 | 核查状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 〔卡内唯一编号〕 | 〔一个可核查主张〕 | 原始观测/作者分析/二次转述/规范要求等 | 〔适用边界〕 | 〔原文实际报告〕 | 页/节/图/表/条款/文件行 | 未核/上下文已核/冲突待核 |

## 作者或发布方的解释与局限
- 原文如何解释，依据是什么：
- 原文明确指出的限制：
- 本轮材料无法回答的事项：

## 本方使用与未决问题
- 可支持哪个主题中的哪项判断，引用哪些声明：
- 只能提供背景、方法、数据、规范或线索的内容：
- 不能据此推出什么：
- 自己的疑问/推断（明确不属于原文）：
- 是否需要补证据；具体看哪里、为了决定什么：

## 复查与变更
- 本人复查日期、范围、发现与处理：
- AI辅助实际做了什么：
- 独立检查：未进行/实际记录：
- 本次相对旧版改了什么、影响哪些引用页：
```

缺失项使用“未读到／原文未报告／不适用（原因）／冲突待核”，不能一律写“无”。“原文未报告”需要说明检索过的范围，不能把没有找到等同于作者没有做。简短引文用于核对；保存页码与忠实释义，不向共享库大段复制版权原文。PDF显示页码与印刷页码不同时同时记下；网页记录标题、段落锚点、访问日和版本。

## 1. 原创研究：写清楚结果是怎样得到的

使用[完整论文证据卡模板](../证据卡规范/02_原创研究论文证据卡模板_V0.3.md)的八部分，并按实际设计补充以下内容。

| 要填的内容 | 必须具体到什么程度 |
| --- | --- |
| 研究问题与假设 | 研究对象、目标变量、作者提出的问题；探索性与验证性目标按原文区别 |
| 设计与分析单位 | 实验/观测/模型/理论/定性；样本如何选、何处何时；独立样本单位是什么 |
| 数据 | 来源、版本、空间时间范围与分辨率、变量与单位、缺测、筛选、预处理、质量控制 |
| 方法 | 输入→处理→输出；关键公式/参数及意义、假设、约束；与已有方法的实际差异 |
| 比较与验证 | 对照、基线、消融、划分、校准与检验区分；时空外推、重复样本或信息泄漏风险按可见材料记录 |
| 结果 | 逐项主结果、反例、失败与无显著结果；指标定义、单位、分母、范围和图表位置 |
| 不确定性 | 原文给出的区间、误差、敏感性、统计检验及条件；不能自行把标准差改成置信区间 |
| 可重复使用范围 | 数据与代码可获得状态、许可证、依赖；作者声称、本人实际检查、本人运行结果分开 |
| 解释与边界 | 作者解释、证据实际支撑、替代解释和本方疑问分开；相关关系不写成因果 |

水文模型尤其核对流域和站点、降雨/流量单位、汇流与调度边界、率定/验证年份、预报提前量、事件划分、空间外推与观测质量。理论研究记录定义、命题、假设、推导位置与适用域；定性研究记录材料选择、访谈/观察过程、编码与解释链，不强填数值显著性。

**接到后续：** 主题比较表引用具体结果与条件；创新候选引用真实局限和未解决问题。方法介绍不能单独证明效果优于其他方法。

## 2. 综述与证据综合：看清综述怎样选材料和形成结论

- **综述类型与问题：** 作者自称类型、研究问题、对象和范围。叙述综述不能自动标成系统综述。
- **检索范围：** 数据库/信息源、检索式、检索时间、覆盖年份、语言、灰色文献、更新方式；未报告逐项注明。
- **筛选与纳入：** 纳排标准、去重、筛选流程、最终纳入数量与研究清单；分清记录数、报告数和独立研究数。
- **提取与质量评估：** 提取字段、检查方式、偏倚或质量工具及适用对象。使用了清单不等于研究质量高。
- **综合方法：** 叙述、分组、证据图谱或定量合并；分组依据、效应量定义、模型、权重、异质性、敏感性及发表偏倚处理，按原文报告。
- **综合结果：** 哪个问题、哪些研究、何种方向/幅度、多少独立资料支撑，结论一致性如何；不要只统计支持论文篇数。
- **证据缺口与局限：** 搜索/语言/时间限制、来源偏倚、重叠队列或共同数据、无法综合的结果、作者确定性表述。
- **关键原始文献：** 综述指向的核心研究链接、原始文献是否实际读过；未读原文时标“综述转述”，不能挂原文引用装作已核。

**接到后续：** 用于建立主题结构和查找原始来源；关键科研判断回到决定性原始研究。多篇综述引用同一研究时追踪重叠，不能当成多次独立验证。PRISMA提供不同综合类型的报告指南，不应被用作统一质量分数。[PRISMA扩展指南](https://www.prisma-statement.org/extensions)

## 3. 调查、监测与统计报告：看清数据代表谁、代表哪一年

- **发布身份：** 发布机构、编制/承接单位、报告号、发布年、数据年、修订版、附表来源；发布日期不等于调查时期。
- **对象与覆盖：** 流域/地区/人群/设施、调查单位、总体范围、统计时期、行政区划变化、是否普查或抽样。
- **调查和测量过程：** 抽样框与设计、样本量/响应、站点或仪器、采集频次、问卷/指标、测量和校准说明。
- **统计口径：** 指标定义、单位、分母、加权、汇总、估算、缺报/漏报/缺测处理、异常处理、质量控制、可比口径。
- **主要发现：** 总量、比例、分布、趋势分别指向具体表/图/附录；记录是否估算、是否调整、是否带不确定性。
- **跨年跨区可比性：** 口径、边界、测站、设备、抽样、价格基期等变化；不一致时不能直接写趋势或排名。
- **解释与建议：** 观测统计、模型估计、部门判断、管理建议分开；机构权威不能代替方法信息。
- **数据可用性：** 原始/汇总数据是否可取、频率、版本、使用许可、限制与更新计划（只记已公布内容）。

**接到后续：** 证明实际问题的规模、区域和时间边界，确定可用数据；统计关联不能直接用于因果机制或模型性能结论。

## 4. 工程项目报告：分清设计预期和运行事实

- **工程与阶段：** 项目名称、位置、规模、设计/施工/运行/后评估阶段、报告编制单位、版本和日期。
- **目标与约束：** 服务对象、功能目标、设计条件、适用标准、边界条件、预算/运行约束，缺失不补造。
- **基础资料：** 水文、气象、地形、地质、资产或监测来源、调查时间、质量与代表性。
- **方案与方法：** 方案选择依据、模型/计算方法、情景、参数、假设、采用标准和不确定性。
- **措施与实施：** 设计采用什么、实际实施什么、何时运行；变更与偏离分别记录。
- **效果证据：** 预测效果、模拟效果、验收记录、实测效果分开；是否有实施前后/对照、观测周期与共同干扰因素。
- **运行与失败：** 故障、极端事件、维护、适用条件和外推限制，来源对应到章节/记录。
- **资源与复用：** 所需数据、设备、人员条件；可取得的文件、版本、保密范围和访问入口。

**接到后续：** 界定工程情景与可行性，产生待验证问题；设计达标、工程验收、科学效果确认是不同事项，不能互代。

## 5. 图书与章节：把概念、定理和经验总结分清楚

- **书目身份：** 作者/编者、书名、版次、出版社、年份、ISBN、译者和原版关系；具体引用章、节、页。
- **本章目的与知识位置：** 介绍什么概念，依赖哪些前置知识，与当前问题的关系。
- **定义与术语：** 定义原意、符号、单位、条件，与主题已有术语是否一致；不能无声换义。
- **理论或推导：** 前提假设、命题、推导路径、公式位置、量纲和适用域；经验公式与定理分开。
- **方法或流程：** 输入、步骤、输出、适用条件与原文例题；例题不当作普遍验证。
- **证据来源：** 作者原创论证、教材简化、经验总结、二次转述分别记录；重要引文能追到哪篇原始材料。
- **边界与时效：** 版次差异、知识截至时间、后续修订信息（核到才填）；年代旧不自动等于错误。
- **本方用途：** 用于定义、解释机制、选择方法还是作为历史背景；关键争议需要另查原始证据。

**接到后续：** 统一主题术语、解释理论假设和建立方法基础；不能只凭教材中的经典案例宣布新方法已被验证。

## 6. 标准、指南与政策：准确引用要求，不当作研究结果

- **文件身份：** 名称、编号、发布机构、版本、发布日期/实施日期、适用地域与对象、状态核查日期。
- **效力与范围：** 文件自述强制/推荐属性、规范/指导/政策角色；废止、替代、修订和过渡信息有官方依据才填写。
- **术语与条款：** 精确条款号、适用前提、阈值、单位、允许偏差、例外与引用文件。
- **测量/计算/验证要求：** 指定方法、采样条件、输入数据、结果报告格式和所需记录。
- **证据或制定依据：** 原文给出的研究基础、咨询过程、依据是否公开；没有写就不推定。
- **对应本项目：** 哪一行为或成果受约束、需要提供什么证据、尚缺哪些条件；不是写一句“遵循相关标准”。
- **边界：** 达到某条款能说明什么、不能说明什么；规范推荐的方法不自动是性能最优方法。

**接到后续：** 约束工程或研究方案，定义必要测量和比较口径。涉及实际合规判断应另核现行官方文本；证据卡本身不代替专业合规审查。

## 7. 数据集与数据说明：判断能不能用、怎么用

- **身份和版本：** 数据名称、生产者、DOI/发布页、版本、发布日期、下载/访问日期、数据说明和许可。
- **生成来源：** 观测、遥感、模拟、再分析、调查或多源融合；仪器、站网、算法和处理级别。
- **覆盖与结构：** 区域/流域、时间跨度、空间时间分辨率、坐标/高程基准、投影、时区、变量名、单位、格式和字段字典。
- **质量与处理：** 精度/不确定性、校准验证方法、质量标识、缺测编码、插补、重采样、过滤、异常和已知问题。
- **适用与偏差：** 覆盖代表性、极值表现、尺度错配、传感器或站点变更、相互依赖数据，按说明与实际检查区别记录。
- **使用约束：** 授权范围、署名方式、再分发限制、访问条件与更新机制。
- **本项目用途：** 计划用哪些变量回答什么、与其他数据怎样匹配；尚未检查的兼容性和缺口。
- **实际取得记录：** OneDrive位置、所用版本/文件清单、必要校验值；未下载、已下载、已检查、已用于分析分开。

**接到后续：** 判断研究设想的数据可行性、准备分析输入和记录版本。数据说明中的精度不是在你这个流域上的已验证精度。

## 8. 软件、模型与代码：区分文档声称、实现和实际运行

- **身份：** 名称、作者/维护方、仓库、关联论文、版本/tag/commit、发布日期、许可证。
- **任务与输入输出：** 实现了什么、输入结构/单位/范围、输出含义、模型假设与不支持的情景。
- **实现关系：** 对应论文哪部分、官方/第三方实现、关键差异、默认参数、数据预处理。
- **运行条件：** 操作系统、语言和依赖、硬件、随机性控制、配置、数据需求；按实际文档填写。
- **验证材料：** 示例、测试、基准、作者结果与已知问题；测试通过不等于科学有效。
- **实际检查：** 只看README/读了哪些文件/安装/运行了什么，分层记录；没有运行不填耗时、性能或复现成功。
- **运行证据（仅发生后填）：** 使用的输入版本、配置、环境、输出位置、误差/差异与失败日志；不得为了完整模板创建虚构运行编号。
- **适配与风险：** 缺失功能、维护状态按检查日期、许可与数据依赖、待补的验证；不因“能运行”就推荐到真实决策。

**接到后续：** 确定方法实现与验证工作量，选择需要核实的技术路径；引用代码不能替代论文结果核查。数据和软件应能识别具体版本与获取条件。[AGU数据与软件说明](https://www.agu.org/publications/authors/journals/data-software-for-authors)

## 保存前统一检查

1. 来源、版本和读到的范围是否准确？是否把二次转述当成读过原始材料？
2. 将用于主题的每条主张是否有可打开来源和具体位置？数字的单位、条件、分母和不确定性是否保留？
3. 原文事实、作者解释、规范要求、自己推断是否清楚区分？缺失是否如实标注？
4. 是否知道这条证据只能支持什么？有没有从相关跳到因果、从设计跳到效果、从运行跳到复现？
5. 是否更新了原文件和受影响链接，避免同一来源多份正式卡？

这些类别与字段是本项目对科研记录需求的设计选择。类型化填写参考PRISMA的适配思路、AGU的数据软件识别要求，声明定位与提取参考[Cochrane资料提取指南](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-05)。它们不构成跨学科统一证据等级，也不意味着所有领域必须采用同一评价工具。
