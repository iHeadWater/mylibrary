# 证据卡验收与错误分级 V0.3

2026-09-03｜本表为待执行的验收设计，不能直接当作一篇论文的通过记录。单人模式记录本人原文复查与AI辅助检查，独立人员检查未开展时明示未开展。

## 1. 验收矩阵

| 编号 | 要检验的具体要求 | 必须查看的证据 | 不通过时的处置 |
| --- | --- | --- | --- |
| Q01 身份版本 | 题名、作者、DOI/来源、正式版或预印本、相关补充与勘误没有串篇串版 | 来源首页、书目信息、实际材料清单及版本关系 | 暂停使用科学摘要，先纠正身份和受影响内容 |
| Q02 覆盖范围 | 拿到什么、读了什么、没读什么分别可见；OCR问题不隐瞒 | 阅读覆盖表及有疑问的原页 | 降低可用范围，未读内容撤去事实断言 |
| Q03 问题对象 | 研究问题、对象、地点/时期/尺度、样本单位完整且属本文 | 引言末/设计/研究区/数据说明 | 缩窄问题与外推范围；不以背景目标冒充本文贡献 |
| Q04 数据方法 | 数据来源—处理—方法—输出可重建；参数未知如实记录 | 方法段、变量表、公式、参数/附录定位 | 补核关键步骤；不能用领域常识补齐 |
| Q05 比较验证 | 对照、评价指标、调参与最终评估的实际用途说清 | 方法与结果中相关设置 | 主结果没有可解释比较时不能给泛化优劣结论 |
| Q06 定量忠实 | 卡片全部已用数字、单位、分母、组别、方向、区间与原报告对应 | Rxx逐行对原文/图表/表注 | 改错后追查顶部摘要、主题候选与问答是否沿用 |
| Q07 声明溯源 | 所有重要声明均有足够具体定位且真的支持对应句子 | Cxx、原页面、限定条件；不是仅文末参考文献 | 无支持部分删除/收窄，不能挂无关引用保留 |
| Q08 解释边界 | 作者报告、解释、推测、转述和本方问题没混写；不升级因果或首创 | 原文措辞、上下文与卡片并排 | 阻断错误优先纠正；“语言优化”不能抹去限定 |
| Q09 结果完整 | 与核心问题相关的不利结果、失效条件和重要矛盾没有被删掉 | 全部核心结果段/图表与摘要对照 | 补齐相反证据后重写结论，不以最优成绩代表全部 |
| Q10 局限与未知 | 作者明确局限和本方尚未知分开；未报告仅限已查范围 | 讨论局限段与缺口查阅记录 | 无依据的批评撤回，真正缺口继续保留 |
| Q11 可用资产 | 声明可用、实际可访问、实际运行、结果核对层级分别报告 | 可用性声明、真实访问/执行记录（如果做过） | 删除没有发生的复现或开源声称 |
| Q12 两层可读 | 上层结论可回链下层，术语一致，八部分实质完整 | 顶部每句对C/R、术语表、八部分内容 | 简化冗余不删决定性条件；数量不足不凑三条结果 |
| Q13 人员与状态 | 不把AI检查或本人复查标成独立人工验收；没有虚填通过日期 | 实际过程记录和任务状态 | 改正状态；独立效果保持未验证 |
| Q14 正式写回 | 同一论文不重复建正式事实；候选与正式写回权限明确 | 已有页查询、候选位置、批准及变更记录 | 停止越界写入，恢复到可审查候选，不擅自修正式科研规则 |

每次实测另填写 `编号／状态／具体定位／实际发现／处置／检查人及时间`。可用状态为“通过（限定范围）/失败/受阻/未执行/不适用（附理由）”；空表不等于全部通过。

## 2. 错误严重度与关闭条件

| 级别 | 典型情况 | 影响范围与关闭证据 |
| --- | --- | --- |
| 阻断 | 串篇串版；捏造样本/结果/引用；数值或方向改变核心结论；丢失否定；关联升级因果；未读冒充全文；未运行冒充复现 | 受影响判断不能交付为可用；保存错误原句、原文定位、修正句，逐处追踪下游并重新核对 |
| 重大 | 重要结果缺比较条件/单位；方法关键链断裂；忽略影响结论的失败情景；关键表述无法准确定位 | 相关部分暂不通过；补证据、收窄结论并核查摘要和引用该内容的页面 |
| 一般 | 不改变科学含义的排版、重复、导航不便或术语呈现问题 | 修正后验证可读性与链接；一旦改变科学意义升级处理 |

未知信息本身不是错误；**把未知伪装成已知**才是错误。等级按对科学含义和后续决策的影响判断，不能只数错别字或机械累计扣分。

## 3. 一张卡什么时候可以交付

“可交付”须同时说明可用范围和未验证范围。对进入事实和摘要的关键科学表述完成来源核对，阻断与重大错误均已处理；剩余未知以明确状态保留，且没有用于支撑超出范围的结论。

材料只覆盖部分正文时，可以交付明确标注的部分阅读记录，不能宣称完整证据卡已通过。自查已完成可支持个人继续使用；不能据此给出独立复核、领域综述完整性、真实科研贡献或实验复现的通过结论。

## 4. 验证设计本身也需要实测

第一篇用于发现模板是否难填、哪里容易遗漏和哪些字段不适用；记录实际问题，不预设必须发现几个错误。修订后先回查同一篇的真实问题；有合适材料再选不同结构的论文检验迁移性。已经反复看过的论文不是盲测，自己检查自己的卡也不是独立评价。

本轮可先验证：链接能打开、模板与十二步一致、Issue产物与验收对应、同步前后正文一致。不能先填“准确率100%”“节约80%时间”之类无测量结果。未来如需量化，必须先定义被检查声明集合、错误单位、核查者和范围，报告分母与未核查项；过程覆盖率不等于科学正确率。

## 5. 真实问题记录模板

| 字段 | 填写要求 |
| --- | --- |
| 问题标识与发现入口 | 对应真实文件版本、C/R、步骤和日期，不虚造案例 |
| 原有内容 | 原句/字段与原文定位，必要短摘录 |
| 错在何处 | 身份、数值、范围、因果、遗漏、导航或其他具体问题 |
| 严重度与依据 | 对哪个判断造成什么影响 |
| 修改与下游影响 | 改成什么，顶部/主题候选/问答是否一起纠正 |
| 复查结果 | 实际检查证据、检查者、时间、未解决项 |
| 防止重复 | 模板提示/操作顺序/可执行检查如何针对原因改变；不只增加口号 |

## 6. 提供给辅助工具的核查任务

让工具按以下顺序工作：读取指定源范围 → 输出其实际覆盖 → 对每项已写声明列支撑位置和上下文 → 标出无法支持、数字或条件不一致之处 → 提出最小修订 → 等人检查。不要让它只回答“这张卡是否严谨”；也不能把工具自行编的定位当作原文。对扫描图表必须查看实际页面，单凭抽取文本不能宣布识别无误。
