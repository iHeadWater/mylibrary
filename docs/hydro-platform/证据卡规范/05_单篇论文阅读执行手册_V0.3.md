# 单篇论文执行手册 V0.3

2026-09-03｜单人执行：你整理、你复查，Codex辅助。先做一篇真实材料的候选卡，按暴露的具体问题调整，不等“两位同学”到场，不把历史六篇任务当个人启动门槛，不据此授权批量加工其他文献。

## 开始之前

第一项实际动作：向本任务提供论文 PDF、DOI 或 Zotero 条目标识，并说明想从它了解什么。只给 DOI 时先定位可用全文；没有全文，先如实登记身份与可读范围，不生成伪装成全文分析的完整结果。当前尚无本轮指定论文，以下动作均为待执行。

阅读一遍[忠实性规范](../证据卡规范/03_证据卡原文忠实性规范_V0.3.md)，使用[完整模板](../证据卡规范/02_原创研究论文证据卡模板_V0.3.md)。已有正式文献页时先定位同一页；新材料先进入本产品包“试运行/候选产物”，正式写入按当前主库入口、编号和批准规则处理。

每篇最少维护三种信息，不要求新建三份平行文档：原始来源入口保存在 Zotero/来源登记；事实与核查放在同一证据卡；任务进度和受阻记录留在对应 Issue 或启动记录。C/R/U 编号只在卡内使用。

## 十二步作业

| 步骤 | 输入与具体动作 | 当步留下什么 | 过关标准与受阻处理 |
| --- | --- | --- | --- |
| 01 接收与去重 | 根据题名、DOI、Zotero标识查同一来源；辨别预印本、正式版、勘误与同研究多报告；读取用户阅读目的 | 身份候选记录、已有页链接、阅读目的 | 身份仍冲突则暂停科学摘要，先解决是哪一篇；不新建重复正式页 |
| 02 锁定来源 | 登记实际拿到的文件/网页、版本、出处、可用范围；有文件才计算校验值；只记录实际取得的补充材料 | Sxx来源清单、正文与附件关系、读取日期 | 知道接下来用哪个版本；没拿到全文就保留“仅摘要/部分正文”限制 |
| 03 通读结构与覆盖 | 阅读可用正文的结构、图表和关键讨论；核对提取文本与页面，识别断栏、公式、图注和表格错位 | 章节覆盖表；不可辨识位置；拟启用类型模块 | 关键方法或结果缺页则记录；不能由摘要或检索片段替代未读部分 |
| 04 重建科学问题 | 找背景中的既有认识、作者明确缺口、本文问题/目标；标对象、空间时间尺度、样本与纳入边界 | 八部分中的第2、3节；问题—证据对应草稿 | 分清领域大问题与本文实际回答范围；没有明示假设不编 H1/H2 |
| 05 画数据方法链 | 逐步记录原始数据→筛选/处理→训练或率定→模拟/分析→输出；登记变量、单位、参数、方程和选择依据 | 第4节数据表、方法链、术语表 | 能看懂作者实际做了什么；未报告项明确标识，不照常识补写 |
| 06 核对比较与验证 | 找对照、分组、调参、验证和测试各自用途；核对时空分割、评价单位、指标及不确定性处理 | 设计/基线/统计表，必要Uxx问题 | 主结论对应实际设计；未知风险保留为疑问，不能断言设计有错或无错 |
| 07 提取全部关键结果 | 按问题逐项查看正文和核心图表；登记数值、条件、对照、组别与不确定性；检查失效和相反结果 | Rxx结果账、第5节、图表导航 | 摘要与正文/图表有冲突则并列；图像读不清不猜数；不只选最优结果 |
| 08 建声明账并起草 | 将核心事实拆成Cxx，配最小充分原文、定位、限定和来源角色；用自己的句式忠实表达 | Cxx声明账、第6—8节及初稿 | 没有依据的句子删去或缩窄；作者推測、前人转述、本方问题分别标识 |
| 09 回原文复查 | 先看源，再看卡；逐一核对关键声明、全部已用数字/单位/比较/因果词/贡献归属；检查漏掉的反例 | 实际复查记录，错误分级与修订 | 发现阻断错误则不可交付为可用；本人和AI角色分开，未开展独立核查如实记录 |
| 10 组装两层八部分 | 核心证据完整后再写快速判断与阅读卡；顶部每个科学表述回到下层C/R；最多选三条决定性结果 | 可读的完整证据卡、术语一致性修订 | 八部分齐但不靠空表凑数；顶部不能夸大或添加下层没有的发现 |
| 11 逐项验收与定界 | 用验收表检查可追溯、忠实、完整性与可用范围；将失败、受阻、未适用分别记录 | 验收表、尚存问题、当前可用范围 | 通过只限明确覆盖的内容；没读/没查的保持未验证，不能批量勾选PASS |
| 12 交付与决定下一步 | 用户查看卡和原文链接；决定结束、补最小材料、处理真实问题或提出主题候选增量 | 交付链接、版本、下一动作或NOOP理由 | 不强制产出Idea/精读；正式主题或规则写回必须走当时适用的授权与版本检查 |

## 每一轮具体怎么安排

第一轮只以“完成一篇可核对的候选卡”为范围。先完成步骤01—03后再估算：正文篇幅、研究类型、主要图表数、是否存在扫描/版本问题，以及关键证据是否在附件。估算填写实际可投入时段，不把“一周”当所有材料都能完成的承诺。

建议把工作分为四次可独立恢复的会话：

1. 来源与范围：01—03；结束时必须知道材料是否足够。
2. 科学结构与证据：04—08；结束时得到方法链、结果账和可核对初稿。
3. 原文复查与修订：09—10；条件允许时与起草分开一个工作时段，减少照着自己的摘要自证。
4. 验收与交付：11—12；同时决定下一篇材料是否需要不同类型模块。

每次结束只记“做到哪、证据在哪、下一步是什么”，不用新造会话数量或阅读时长作为科研质量指标。材料复杂可拆分更多次，缺原文则暂停有关结论，不拖着“进行中”假装持续产出。

## 受阻记录（填在卡末或对应 Issue）

| 字段 | 内容提示 |
| --- | --- |
| 阻碍的判断 | 哪个C/R或研究问题无法继续，不写笼统“资料不足” |
| 已查看 | 实际版本、章节、图表及访问尝试 |
| 具体缺口 | 哪个定义、数据、表注、版本或参数还缺 |
| 当前处理 | 删除/缩窄相关表述，保留未知，或暂停整卡使用 |
| 最小恢复条件 | 用户提供哪一页/文件，或核实哪一项即可继续 |
| 恢复入口 | 回到第几步、哪个C/R/U，原有正确部分是否可保留 |

## 交付时怎样讲清楚

交付说明写明：本文实际读取范围；最主要的原文发现及定位；尚不能支持的判断；本人原文复查与AI检查各自做了什么；下一步是否有决定性证据缺口。不能只说“已生成证据卡，检查全部通过”。

本次规范建设的验收与真实论文处理分开：文件、链接和任务定义可以在现在核对；模板是否足以减少漏读与错译，需要真实论文试用后据问题记录判断。
