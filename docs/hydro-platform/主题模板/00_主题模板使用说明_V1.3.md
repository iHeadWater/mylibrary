# 主题模板使用说明 V1.3

主题工作现在明确分成三个文件对象。它们承担不同职责，不能合并成一张“万能主题表”。

| 文件对象 | 什么时候建立 | 主要回答什么 | 能否承载科研结论 |
| --- | --- | --- | --- |
| [初步主题与人工筛选模板](01_初步主题与人工筛选模板_V1.3.md) | 文献分组或主题模型发现一个可能方向时 | 这组材料为什么聚在一起、可能研究什么、边界哪里不稳、人工如何处置 | 不能，只用于筛选 |
| [既定主题深度综合模板](02_既定主题深度综合模板_V1.3.md) | 人工决定 `establish`、`rename_then_establish` 或 `merge` 后 | 既定主题的核心问题、证据链、方法与数据谱系、万字综合、独立见解和反向补核 | 可以，但每个判断仍须回到已核 Claim |
| [主题工作流运行账模板](03_主题工作流运行账模板_V1.3.md) | 每次从一批文献发现并推进主题时 | 本次输入、路线、筛选决定、优先级、全文队列、反馈和重算 | 不能，它只记录过程和导航 |

Skill 中的同名文件是机器生成所用的可执行骨架；本目录保留供人在 GitHub 和 Obsidian 中直接查看、复制和讨论的公开模板。两边字段应保持一致。正式运行时，一个科研内容只保留一份实际 Markdown：初步主题记录筛选事实，既定主题保存通过筛选后的科研综合，运行账只保存批次过程和链接。

## 正确顺序

1. 冻结研究问题、用途、语料范围和本次允许形成的结论层级。
2. 选择小样本深读或大语料发现路线，生成一个或多个初步主题。
3. 对每个初步主题核对形成依据、代表文献、离群项、相邻主题、边界和偏差。
4. 人工作出且只记录一个当前有效决定：建立、改名后建立、合并、拆分重审、观察、补材料后再定或拒绝。
5. 只有前三类决定可以建立既定主题，并且必须写入决定编号、决定者、日期、理由和来源初步主题。
6. 在既定主题内选择关键全文、建立或补核证据卡、执行 Claim 准入和可比性裁决。
7. 完成不少于 10,000 个可见科学字符的主题深度正文；材料不足时标记受阻，不能用背景和套话凑字数。
8. 将发现的问题反馈到原证据卡、检索语料或发现模型，修改后重算受影响部分。
9. 导师决定继续深化、调整边界、合并拆分、观察或停止。

## 七种人工筛选决定

| 决定 | 何时使用 | 后续动作 |
| --- | --- | --- |
| `establish` | 名称、问题与边界已经足够清楚 | 建立一个既定主题 |
| `rename_then_establish` | 方向成立，但现名只是关键词或范围不准 | 改名并建立既定主题 |
| `merge` | 多个初步主题实质回答同一问题，单独保留会重复 | 合并后建立一个既定主题 |
| `split_and_rescreen` | 一个初步主题混入多个不能共用证据链的问题 | 拆为新的初步主题，再次筛选 |
| `watch` | 有方向信号，但当前价值或证据不足 | 保留观察，不进入既定主题证据链 |
| `supplement_before_decision` | 缺少能改变判断的关键材料 | 写清最小补充材料和停止条件 |
| `reject` | 只是关键词共现、机器误分或与任务无关 | 记录理由后停止推进 |

模板中的空字段表示尚未取得或尚未判断，不能凭常识补齐。年份、期刊影响力、引用和主题增长率只用于安排阅读资源，不能替代全文证据，也不能自动决定主题是否成立。
