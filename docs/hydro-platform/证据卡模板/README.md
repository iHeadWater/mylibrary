# 证据卡模板使用说明 V1.7

每个来源生成一个独立Markdown。新建时把[公共来源骨架](00_公共来源证据卡骨架_V1.7.md)与01—08中恰好一个来源类型模块组合；需要跨来源作平台判断时另用09决策卡。类型模板告诉你“这种来源如何产生证据”，公共骨架规定所有卡都要写清的研究问题、数据、方法、结果、边界、用途和原文定位。

## 九种卡片怎么选

| 编号 | 来源或卡片 | 必须抓住的科学核心 | 不能替代什么 |
| --- | --- | --- | --- |
| 01 | [原创研究](01_原创研究证据卡模板.md) | 研究问题、样本与独立单位、数据生成链、方法转换、对照与验证、决定性结果、贡献和结论边界 | 单篇论文不能替代领域共识或新颖性检索 |
| 02 | [综述与证据综合](02_综述与证据综合证据卡模板.md) | 综述问题、检索与筛选范围、证据单位、偏倚评估、综合方法、异质性、证据重叠和结论确定性 | 发表综述不能替代平台自己的Claim准入和决策综合 |
| 03 | [调查监测与统计报告](03_调查监测与统计报告证据卡模板.md) | 总体／站网覆盖、指标与分母、监测和修订链、缺测与质量控制、时空可比性、不确定性 | 描述性变化不能自动证明因果 |
| 04 | [工程项目报告](04_工程项目报告证据卡模板.md) | 工程阶段、证据层级、标准与工况、设计／施工／运行差异、审查验收、失效模式和剩余风险 | 验收通过不能自动证明长期或极端工况安全 |
| 05 | [图书与章节](05_图书与章节证据卡模板.md) | 版次章节、原文概念或公式、前提与推导、译名、上游引用链、适用域和例外 | 教材或作者综合不能冒充一手实证结果 |
| 06 | [标准指南与政策](06_标准指南与政策证据卡模板.md) | 文件效力、版本与有效期、条款属性、适用主体、例外、替代关系、符合性证据和技术依据 | 规范权威不能自动证明科学最优或可迁移 |
| 07 | [数据集及数据产品](07_数据集及数据产品证据卡模板.md) | 不可变版本、生成链、变量单位、时空支持、质量与缺测、派生历史、许可和任务适配 | 可下载不等于质量良好或适合当前任务 |
| 08 | [软件模型与代码](08_软件模型与代码证据卡模板.md) | release／commit、模型与实现关系、依赖和输入输出、运行证据层级、基准独立性、失败条件和漂移 | 能安装或运行不等于复现论文，更不等于科学有效 |
| 09 | [平台证据综合与决策](09_平台证据综合与决策卡模板.md) | 研究问题、Claim纳入排除、独立性与版本谱系、冲突、覆盖、迁移、六维画像和当前决定 | 它不是新来源，不复制原卡正文，也不等于导师批准 |

## 所有实质来源共同要求

1. 开头先让人看懂来源研究或报告了什么、用了什么材料和方法、得到什么结果、最重要的限制是什么。
2. 正文沿来源自己的论证链写，不能机械逐标题填充。没有对应内容的栏目写明原文未报告及影响，不凭常识补齐。
3. 数字保留对象或分母、单位、时间、空间、比较条件、不确定性和原文定位；结果不是脱离条件的数字清单。
4. 作者明确陈述、原文可直接推出的事实、分析者判断和后续设想分开表达。
5. 实质全文或部分主文的L1可见科学正文至少5,000个非空白字符，L2／L3至少6,000字符；字数来自有效信息，不能来自重复、背景、OCR、参考文献和机器字段。
6. 校勘备注、机器状态和Claim JSON默认折叠，读者首先看到科学内容。
7. 普通来源卡不设通用“复现需要什么”章节。数据和代码只在改变证据强度时说明；软件卡可记录运行层级，因为运行本身就是被审查对象。
8. 短公告、目录页或简短政策发布页按真实内容缩短，明确`reading_scope`，不能为达到字数门槛伪造研究设计。

## 完成级别

| 级别 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| L0 | 登记身份、版本、正式入口和缺失材料 | 形成科学内容判断 |
| L1 | 快速理解和决定是否继续读 | 作为主题承重证据 |
| L2 | 建立至少一项已定位、已核的决定性Claim | 自动代表全文所有结论都可靠 |
| L3 | 在动态精读三门同时满足时补核方法、图表、附录、版本或代码 | 因论文重要或有附件而强行触发 |

机器校验只检查结构、字符、定位字段和重复等可计算问题。研究问题是否抓准、方法是否理解、关键结果是否遗漏、作者原意是否忠实和结论边界是否合理，必须由人阅读原文判断。
