## 研究要解决什么问题

写清对象、场景、作者明确提出的缺口和要回答的问题。不得只写领域背景，也不得把分析者的期待改写成作者原意。

## 研究对象与边界

写清地点／流域／系统、事件或时期、分析尺度、样本或独立单位、比较对象、纳入排除条件及目标应用情境。

## 数据到底是什么

用表格区分观测数据、派生数据、模拟输入、情景假设和外部资料；记录来源、时期、样本量、分辨率、变量、预处理、在校准／验证／测试中的用途和可获得性。原文未报告的逐项写明。

| 数据或材料 | 来源与取得方式 | 时空范围／样本 | 变量、单位与分辨率 | 预处理与质量控制 | 在研究中的用途 | 原文位置 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

## 方法是怎样一步步得到结果的

按输入→处理／模型→耦合或推断→验证／比较→输出说明。只列软件名、算法名或公式名不算方法说明。把关键假设、参数来源、中间产物、分析单位和信息泄漏风险写进实际步骤。

## 验证和比较是否站得住

说明基线、对照、指标、校准与验证是否独立、敏感性／不确定性，以及本轮未核到的关键检查。预测性能、机制解释、因果效应和工程可用性是不同结论，必须分别判断。

## 研究设计与证据链

### 输入为什么能回答问题

说明观测、样本、情景或模型输入与研究问题之间的对应关系。

### 数据怎样经过方法变成结果

按实际模块、变量、参数和中间输出展开，不能使用可复制到任意论文的套话。

### 关键结果怎样被比较或验证

连接具体表图、指标、对照、敏感性或现场证据，并说明验证层级。

### 证据链最弱的一环

指出哪个输入、变换、比较或外推仍缺证据，以及它影响哪条结论。

## 最关键的结果

用三至五组可解释结果回答研究问题。保留数值的单位、分母、条件和不确定性；无明确数值时说明证据形态和定位状态。结果之间有条件差异时解释差异来源，不能堆成数字清单。

| 结果要回答的问题 | 原文报告的结果 | 条件、分母与不确定性 | 表／图／页码 | 对研究问题意味着什么 | 不能推出什么 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

## 作者解释、分析者判断与贡献

把作者机制解释、本文实际贡献和分析者对平台用途的判断分开。贡献要回答本来源相对既有工作新增了什么；分析者提出的假设或迁移方向不能伪装成原文结论。

## 对当前科研工作的用途

说明可以支持什么、不能支持什么、需要与哪些证据配合，以及它具体影响变量选择、比较设计、模型结构、解释框架或下一项可证伪问题的哪一步。

## 结论边界与下一步精读

把数据、设计、模型、空间、时间、推断和迁移边界连接到受影响的具体结论，并列下一步需要重开的页、表、图或附件。普通来源卡不设置通用“复现需要什么”章节；数据或代码只在改变证据强度时说明。

## 正文深度与反套话要求

对实际读取完整或部分主文且包含实质研究设计的来源，L1可见科学正文至少5,000个非空白字符，L2／L3至少6,000字符。题录、链接、参考文献、校勘备注、机器字段和默认折叠内容不计入。篇幅只能来自原文的研究问题、数据、方法、比较、结果、图表、贡献和边界；不得靠重复摘要、领域背景、OCR或模板句凑数。短公告、目录页或简短政策发布页应如实缩小`reading_scope`，不能伪造论文式内容。
