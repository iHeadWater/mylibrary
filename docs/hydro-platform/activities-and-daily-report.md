# 关键事件与老师日报

2026-09-09 实现。此功能不调用AI，不评价科研质量，不做排名，不推送GitHub。它只回答：本日发现了什么、哪些卡片已完成、还有什么在等待或阻塞、最近一次系统运行是否成功。

## 已确认用户故事与验收

本页保留 US-09 和 US-13 的验收语义，但不再依赖旧的用户故事文档。该功能没有增加逐卡人工核验。

### US-09A：关键贡献记录

作为导师，我希望分清谁新增论文、谁补PDF、系统完成了什么，以便掌握实际进度。

讨论边界：人只归属明确提供的 Zotero 用户ID；系统行为是系统身份；没有身份就是未知。第一次启用只建立历史基线，不把现有论文都算作新贡献。

验收：

1. 父条目/PDF分别产生 PAPER_ADDED/PDF_ADDED，用各自的创建者元数据；不使用论文作者、当前登录者或最后修改者替代；
2. 卡片完成及运行阻塞记录为系统行为，不额外调用模型；
3. 首次观察的历史条目/附件/已完成卡只进入基线，后续重复观察不产生重复事件；
4. 可共享账本保留后，即使换一个全新的本地运行目录，已记录事件也不重放；
5. 账本包含群组校验、确定性事件ID、内容指纹和进程互斥；损坏或修改冲突时不覆盖；
6. 只保存必要身份、文献Key、标题、状态和观测时间；不复制PDF、全文、绝对存储路径、凭据或原始诊断输出。

### US-13A：进度与阻塞摘要

作为导师，我希望看到一份简短的当日新增、完成和当前待处理摘要，以便识别真正的停滞。

讨论边界：按“首次观测日期”统计本日事件，同时列出跨日未解决事项。日报文件存在不等于定时器或模型服务正常；必须显示最近统一运行的时间与状态。

验收：

1. 同一条 run-once 在主流程后自动生成日报；单独 daily-report 不扫描Zotero、不调用模型；
2. 区分本日新事件、当前有效粗卡总数和持续等待/阻塞，不把历史卡数量写成当天产量；
3. 没有事件也生成摘要；没有当天运行记录时明确说明，不能伪称系统已按计划运行；
4. 时间边界来自总配置UTC偏移，原始时间在JSON中保留；
5. 已完成任务的卡缺失/被修改、最近运行失败或输出冲突，要出现在阻塞说明中；正文以元数据转义方式渲染，避免标题变成外链/HTML；
6. 同日重复生成更新系统日报；人工修改保留并报冲突；JSON已写、Markdown未写的中断可无模型修复。日报失败不撤回已保存卡，也不重跑模型。

## 命令

在仓库根目录运行，统一前缀 `uv run hydro-platform`。正常操作仍是一条：

```powershell
uv run hydro-platform run-once --json
```

只更新贡献记录或日报：

```powershell
uv run hydro-platform activity-sync --json
uv run hydro-platform daily-report --json
```

activity-sync 只读访问配置的共享库；第一次建立基线，后续发现新增/补充。daily-report 只读取已有账本、任务与最近运行报告，不保证刚加入Zotero的论文已被扫描。两个命令均不调用模型。

总配置新增：

```json
"activity_reporting": {
  "enabled": true,
  "utc_offset_minutes": 480,
  "system_actor_id": "SYS-CARD-01"
}
```

enabled 控制 run-once 自动接入；显式运行两个维护命令不受此开关限制。480表示团队统计使用UTC+08:00；这是固定偏移，不自动处理其他地区夏令时。文件根目录沿用 paths.activity_dir、paths.members_dir、paths.reports_dir；不需改代码。

## 保存位置和保护

- `paths.activity_dir/ledger.json`：可共享的基线和去重事件账本。它不是可丢弃缓存，备份时需与其他持久化成果一起处理。
- `paths.reports_dir/daily/YYYY-MM-DD.md`：老师阅读的当日摘要。
- `paths.reports_dir/daily/YYYY-MM-DD.json`：用于重建 Markdown 和中断恢复的结构化记录。
- `paths.members_dir/members.json`：可选的人工身份映射；没有时不猜测人名。格式见[权限与数据归属](permissions.md)。

### 老师进度摘要

`paths.reports_dir/daily/` 按日期保存“新增、完成、等待与阻塞”的 Markdown 摘要及配套 JSON。同一天一对文件：`YYYY-MM-DD.md` 给老师阅读，`YYYY-MM-DD.json` 是结构化数据，方便程序检查、恢复和后续汇总。内容包括当日新增事件、完成卡片、等待/阻塞、最近运行及主题处理状态；日期划分来自 `activity_reporting.utc_offset_minutes`，当前为 UTC+08:00。

run-once 在监控路径中刷新摘要，`daily-report` 可单独刷新，两者的摘要生成都不额外调用 AI，也不会为缺卡自动制卡，更不注册计划。报告来自本机已观察的共享库、任务、成果和关键事件，不等于云端最新全量状态；报告文件存在本身不证明计划正在正常运行，每日触发是否生效需以 `schedule-status` 为准。

不要在生成的 Markdown 里写个人笔记：检测到人工改动时程序会保留并停止覆盖。日报和事件账本是持久化科研产物，但当前被 `.gitignore` 排除，不应通过 Git 提交共享；团队需在 Git 之外配置备份或共享位置。原始日志留在 `hydro-platform/.runtime/`。贡献者字段缺失时如实记录未知，不根据论文作者或用户名猜学生身份，不用于排名；不通过微信或邮件自动发送。

### 关键贡献账本

`paths.activity_dir/` 保存适合团队共享的关键事件，用于帮助老师掌握流程进度和发现阻塞。`ledger.json` 基线与去重账本由 `run-once` 自动维护，也可运行 `uv run hydro-platform activity-sync --json`。首次启用不回放历史贡献。不要把此账本放进可丢弃的运行缓存或手工改哈希。

第一版关注：成员新增 Zotero 论文父条目；成员给已有条目补充 PDF；系统成功创建或更新证据包；系统发现缺少 PDF、PDF 不可读或制卡失败。

同一论文可以有多位贡献者，每种行为分别记录。事件不得用于学生排名或绩效评分，也不得包含原始运行日志和密钥。贡献者只能来自本机 API 明确返回的身份，再用 members 中的映射转换；未知身份不能猜测。账本由程序维护，日常阅读[老师进度摘要](#老师进度摘要)，不手工改账本或内容指纹。

CARD_COMPLETED 表示系统首次确认卡片已保存，可能是生成或草稿恢复，不等于当天调用了模型。TASK_BLOCKED 按“文献+状态+原因”去重，记录该类问题首次出现，不把每次重试都算一次贡献；持续阻塞以日报的当前事项为准，不把它当完整状态审计流。

首次启用前已完成的卡片只进入基线。未完成的占位卡在后续完成时仍会产生完成事件。run-once 在制卡前建立/更新基线，在制卡后记录完成，使用同一份扫描快照，不为贡献记录重复拉取一轮文献列表。

账本、日报和知识文件都是本地成果；本次不自动提交/推送。只有实际备份或推送后，换机才能从对应备份取回它们。账本遗失后无法可靠恢复旧贡献历史，不能把系统状态恢复等同于贡献历史恢复。

## 身份来源的实测限制

Zotero 官方文档将组库的 createdByUser/lastModifiedByUser 列为系统生成的 meta 字段；本实现只读取创建者字段，最后修改者不等于新增者。[官方API说明](https://www.zotero.org/support/dev/web_api/v3/changes_from_v2)

2026-09-09 对本机 Zotero 9.0.6、qinjiajun（6618088）的实际检查：接口未返回这些创建者身份字段。因此后续若仍缺身份，就记录 UNKNOWN，不读取个人库、数据库或云端凭据来猜。用模拟明确用户ID的样本已验证多人分别归属，但真实多人身份覆盖尚未验收。
