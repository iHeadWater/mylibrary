最新保存决策（2026-09-09）：按模板写作，程序只校验流程，不把正文标题、表格、标签、编号、占位词或措辞当作保存门槛。新产物 PROCESS_VALIDATED 表示流程通过，正文 NOT_CHECKED，不是内容质量认证。详见 [保存边界](single-agent-rough-card.md)。

## 用户任务与范围

作为制卡机维护者，我希望只运行一条命令，系统就能发现待处理论文、处理后补 PDF、生成首张详细粗卡并说明结果，以便不再逐条操作命令或输入论文 Key。

设计依据：[自动化边界](automation.md)、[单 Agent 制卡](single-agent-rough-card.md)。当前入口已包含按配置的Zotero启动/有限等待、贡献日报和主题链路；调度注册与环境安装仍是独立命令，run-once不安装系统任务或软件、不运行模型探针、不生成idea、不执行Git操作。

## 操作

```powershell
# 在仓库根目录运行
uv run hydro-platform run-once --dry-run --json
```

这是只读本地预览：显示 tasks.json 中的任务和限额，不扫描 Zotero、不写摘要、不检查账号、不调用模型。没有本地清单时显示空任务，不意味着共享库为空。

正式运行前保持 Zotero 可访问、共享库及 PDF 已同步、Codex CLI 已登录，并使用已经验证的本机 PDF 工具环境：

```powershell
uv run hydro-platform run-once --json
```

不需要 item-key，也不需要按篇数改配置。默认自动逐篇处理本轮扫描到的全部可制卡论文，每篇完成立即正式保存到 `evidence-packs/EV-<Key>-<标题短名>/card.md`，不是试运行预览，不要求手动转正。已有卡不自动覆盖。`--no-progress` 关闭 stderr 进度，stdout 保留最终 JSON。

## 运行顺序

整轮互斥 → Zotero就绪检查（按配置单次启动/有限等待）→ tasks-sync扫描及PDF门禁 → 核对证据包/待保存记录 → 为选中论文建骨架 → 制卡器非模型预检 → 串行制卡并保存 → 按配置的主题/贡献日报 → 本地摘要。

有等待/延后但无错误时返回COMPLETED_WITH_PENDING，不再冒充全部完成；调度会有限补查。PDF正在同步/索引时暂缓自动主题，单纯未添加PDF不阻塞其他粗卡。详见[启动与等待](zotero-readiness.md)。

- tasks-sync 已扫描共享库，不再机械地先跑 scan；此命令不更新独立的 zotero-snapshot.json。
- 本轮只有一次扫描，形成固定队列；内部逐篇处理而不是多模型并发，不在结尾重复扫描或无限追赶新入库。运行期间新入库的论文留到下一次命令。
- 处理新条目，也处理后来补齐 PDF 的旧条目；等待和超过限额的论文不会被丢弃。
- 只有存在待制卡任务时才检查制卡器和模板，不调用 generator-smoke-test。
- 已生成卡片核对 manifest 和文件指纹。人工编辑、PDF 输入变化、清单不完整时保留文件并报告阻塞，不静默覆盖。
- 本地任务状态丢失后，扫描可重建任务；完整且来源一致的包可恢复 COMPLETED，无需重复调用模型。这不等于新电脑安装、登录和调度恢复均已实现。

## 配置

日常使用无需修改配置。只有主动限制规模、时间或调整故障策略时才修改 `hydro-platform/config/config.json` 的 pipeline。现有本地配置与示例已迁移为处理全部；其他旧配置的明确限额仍遵守，省略字段则采用新默认值，未知字段拒绝。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| max_items_per_run | null | 默认处理全部可制卡论文；可选正整数才限制单轮尝试数，失败也占一次 |
| max_run_seconds | null | 默认无整轮截止；可选正整数才限制启动/调用时间，单篇超时仍保留 |
| max_attempts_per_item | 3 | 当前任务输入下累计最多领取/尝试三次，包含首次 |
| retry_cooldown_seconds | 3600 | 暂时性失败到下一次自动尝试的最短间隔 |

不保证多篇总耗时等于单篇耗时；本阶段串行生成。单篇超时由 card_generator.generation_timeout_seconds 限制，不因去掉整轮上限而无限等待。如果主动设置整轮预算，它不是强杀 Python 的硬时限：扫描、恢复、保存和清理可能使总耗时超出预算。不会在进程内等待一小时冷却，也没有无限重跑循环，每篇本轮只尝试一次。

自动模型重试只限明确的连接/服务、限流、模型超时或过期租约。认证、配置、阅读、空输出等流程失败不盲目重读论文。历史结构、归因、占位词、措辞或分类元数据拦截的完整草稿可以不调用模型地恢复；来源不符、输出损坏、模板索引不存在和覆盖冲突仍阻塞。正文差异不再产生失败；单篇流程错误不影响其余可处理论文，共享服务不可用则延后剩余模型任务。

达到次数上限显示 ATTEMPT_LIMIT；非暂时性失败显示 NON_RETRYABLE_FAILURE。次数来自本地 tasks.json，改变输入或丢失本地状态可能重置它，不是永久计费账本；手动单篇命令也不由统一入口的限额限制。

## 中断与冲突保护

1. 整轮由操作系统持锁。位置由 paths.lock_file 派生为 `<原文件名>.pipeline`。第二个 run-once 返回 ALREADY_RUNNING，不扫描或调用模型；持有进程退出后锁自动释放。底层清单短锁和论文租约继续保留，有效论文租约显示 WAITING，不抢占。
2. 三个正式文件写入前，先把已校验的 card、manifest、audit 和原 manifest 保存到 paths.lock_file 同目录的 pending-publications/<群组>-<Key>.json。中断后只对原占位内容或与记录相同的内容补齐，不重跑模型。人工改动、输入变化、记录损坏则保留全部内容并报告冲突。

成功补齐完整包后删除对应本地待保存记录；如果包已完整但任务未完成，只补状态。

历史失败恢复：run-once 选择当前 Key/PDF 指纹匹配的最新 card_writer 草稿，要求完整成功输出、模板 ID 有效、正文非空、任务输入未变化且正式位置仍是占位卡，不再检查正文结构或归因。满足后原样正式保存，任务记 COMPLETED，不增加模型次数；最新输出损坏时不倒退选更旧草稿。

不再为【AI推理】/【AI 推理】等写法逐项增加兼容补丁；所有这类正文检查均不在保存路径中执行。模板继续指导模型清楚区分事实和推理，保存不代表程序核实了其正确性。

这类正式卡的 generation_provenance / quality_status 为 DRAFT_RECOVERED，采用独立的 rough-card-draft-recovery-v1 记录。正式保存不等于独立科研验证：旧执行回执缺失、原生成时间/原模板版本未知均如实记录，不用当前值冒充。当前模板只记 checked_against_*。阅读失败或网络中断未产生完整输出不能据此恢复。显式 evidence-draft-export 仍保留“仅导出预览”的旧用途，正常一键流程不需要它。

待保存记录位于配置的 .runtime 中，不进入 Git。它含生成内容但不含 PDF 原文件或凭据。模拟中断测试不等于所有硬件故障下的持久性保证；硬盘损坏仍依赖已备份的仓库及 Zotero。

## 运行结果

最终 JSON 包含 scanned_task_count、new_discovered_count、generation_attempt_count、counts（completed/recovered/skipped/waiting/blocked/failed/deferred）、每篇结果及 report_path。进度显示队列位置和正式 card.md 路径，已完成卡再次运行也列出路径。新发现是本地任务盘点差值，不等于某学生当天贡献。

Python 将摘要写入 paths.logs_dir/pipeline-runs/<时间>-<运行ID>.json，不额外调用 AI。退出码 0 表示无失败阻塞或已有实例在运行；3 表示存在失败/阻塞；Ctrl+C 为 130。摘要保存失败不撤销已完成卡片、不重跑模型。

## 验收标准（3 C / INVEST）

1. 单次命令完成本轮多篇正常论文链路，无需改配置或再次启动下一批，每篇即时正式保存；第二次不调用模型、不修改已有卡。
2. 缺 PDF 保留等待，后来补齐无需填写 Key；超过篇数限额的论文不建无用骨架、不丢任务。
3. 两个进程同时启动只有一个进入扫描制卡；退出的锁持有者不阻塞后续运行，有效论文租约不被抢占。
4. 认证失败、限流、持续失败、冷却和时间预算产生明确结果，不无限重跑，不运行模型探针。
5. 分别在 audit/card/manifest 写入时中断，或文件完整后、任务完成前中断，后续无需模型即可恢复；人工修改保留并报告冲突。
6. dry-run 不产生网络、模型或文件写入；实际运行只生成本地摘要，不执行 Git 或安装调度。真实 Zotero/订阅模型验收由用户运行，不以模拟测试冒充完成。
7. 正式生成、试运行和草稿恢复都不执行正文格式/内容检查或额外模型复核；完整草稿可恢复，来源错误、空/损坏输出、并发覆盖和已有人工修改仍受保护。
