# 主体卡代码校验

拿草稿和它的输入记录，按**确定性规则**给出 `PASS` / `FAIL`。

校验器**不调用模型、不读 Zotero、也不重新读 PDF** —— 它只比对已有的输入、阅读记录和所选版本的资产。

## 怎么用

```bash
uv run hydrolitagent cards evidence-validate --draft <草稿目录>/draft.json --paper-input paper-input.json --json
```

**完全离线** —— 不需要 Zotero、PDF 文件、群组、Poppler 或模型登录。
所以它也是唯一能在**还没配任何东西**时跑得通的一步。

校验记录**追加**在草稿旁边，**原草稿逐字节不变**：

```text
<草稿目录>/validations/<校验ID>/validation.json
```

## 结果怎么读

| 结果 | 含义 |
|---|---|
| `PASS` | 已实现的确定性规则通过 —— **不等于**科研正确，也不等于正式发布 |
| `FAIL` | 看 `errors` 里的 `code` / `path` / `message`，修掉真正的原因再重跑 |
| 有 warnings | 逐条看。警告**不一定**让校验失败（例如「正文偏短」只是一条提示） |

## 关于「表格被截断」的警告

正文声称某张表的数值「被截断」时，会记一条 `CARD_TRUNCATION_CLAIM_UNVERIFIED`。
它只认两种措辞：`截断为「X」` 和 `末位被截断`。

这条规则**只读草稿**。校验记录里的 `warnings` 参与绑定，下游复核
（`load_validated_subject_card`）手里只有草稿和输入记录，拿不到转换后的 `paper.md`；
规则一旦依赖外部文本，存下来的记录和复核结果就永远对不上。所以它不判定真假，
只要求作者把被截断处的**原文**引出来，或直接给出完整数值。

2026-11 的一张 OlmoEarth 卡片，对 `6.2M`、`6.67 kL` 这两个在 `paper.md` 里完整可读的
数值都写了「截断」——真正的成因是转换器把表拍平了，模型据此编了一个信息边界。

## 边界

- **`PASS` 只表示代码规则通过**，不证明原文支持结论、也不证明科研内容正确。
- 规则失败的草稿**不会被放行到下游** —— 不会把失败草稿伪装成已通过校验的产物。
- 校验记录**不是密码学签名**：有写权限的人仍能改它，所以下游会**重新运行规则**。
- 记录写入失败时，**不会**返回可供下游使用的 `PASS`。
- **正式发布不在这一步。**
