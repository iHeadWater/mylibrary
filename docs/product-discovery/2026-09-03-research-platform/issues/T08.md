# [T08] 完成第一轮联合验收并形成第二周问题清单

里程碑：M1 ｜ 认领角色：两位同学交叉验收；导师确认内容及下一步 ｜ 建议工作量：约半天

状态：待认领。GitHub Assignee、实际日期、验收结果以对应 Issue 为准；本文为创建时的任务定义。

## 为什么做
第一周需要一份能判断继续还是返工的证据，不能只报告生成了多少文件。

## 输入与前置依赖
T03—T07 交付链接和运行记录、本目录验收清单。

前置任务：[T03](T03.md)、[T04](T04.md)、[T05](T05.md)、[T06](T06.md)、[T07](T07.md)

## 做什么
沿“来源—卡片—主题—对话—补读—Idea—换机”演示，逐项填写实际结果和证据。分别报告工具可用、帮助理解、Idea 值得继续；将失败转换为第二周可重现的问题。

## 交付物
- 填写后的联合验收记录及证据索引。
- 按影响排序的问题清单：触发步骤、预期与实际、证据、影响用户、处理建议。
- 本轮结论与导师反馈；存在阻断项时明确暂不能通过 M1。

## 完成标准
- [ ] 清单每项为通过、失败或受阻，并有证据链接和检查者；不把空白当通过。
- [ ] 重复、缺全文、条件差异、基准过期、补读后仍不足五类异常均有验证或明确受阻原因。
- [ ] 至少 3 条主题判断完成来源追踪，并记录关键误解与返工。
- [ ] 用同一五项评分口径记录入门用时和理解质量；无可比基线时不宣称提效百分比。
- [ ] 第一周问题按阻断、显著影响、可延后排序；导师确认下一轮先解决什么。

## 不在本任务范围
不因 CI 通过宣布科研结论正确，不用小样本推广统计结论，不自动新增大规模处理任务。

## 受阻时怎么处理
任一关键步骤受阻则 M1 保持开启；“演示过”与“验收通过”分开记录。

## 如何提交与验收
认领后填写一位整理同学、一位同伴检查同学及预计交付日。交付候选文件或 PR 链接、基准版本和逐项证据；检查者写明结果。涉及科研取舍的事项由导师确认。仅创建文件或合并文档 PR 不关闭本 Issue。

关联旧需求：无直接对应的旧功能单。 旧单保留为能力方向；本单只验收当前小样本闭环的一个交付，不代表旧单的全部范围完成。

需求依据：[产品文档](../科研知识平台_产品文档.md)、[里程碑计划](../里程碑计划.md)、[验收清单](../验收清单.md)、[仓库兼容说明](../仓库兼容说明.md)。
