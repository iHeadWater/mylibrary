# [T04] 交付一页能帮助新人理解领域的主题论述

里程碑：M1 ｜ 认领角色：主题整理同学；另一位同学试读；导师评议 ｜ 建议工作量：约 1 天

状态：待认领。GitHub Assignee、实际日期、验收结果以对应 Issue 为准；本文为创建时的任务定义。

## 为什么做
学生需要理解研究路线及其依据，主题页应帮助解释问题，而不止把文献按词分组。

## 输入与前置依赖
T01 确认的研究范围、T03 通过校准的样本卡、产品文档第 3.2 节。

前置任务：[T03](T03.md)

## 做什么
围绕本轮学习目的组织一篇连续可读的主题页：问题边界、路线演进、方法适用条件、当前认识、未知和阅读路径。逐条说明文献如何支持或限制论点。

## 交付物
- 一份候选主题正文和来源导航；保存于 T01 指定位置。
- 试读记录：新读者解释了什么、哪里误解、据此做了什么修订。

## 完成标准
- [ ] 主题页可回答问题是什么、主要路线有哪些、哪些认识可信及哪些仍未知。
- [ ] 随机抽 3 项主要判断，均能从主题进入卡片并定位原始来源。
- [ ] 至少比较两条研究路线或说明为何现有材料仅支持一条；比较写明条件而非强求矛盾。
- [ ] 另一位同学约 30 分钟试读后按问题、路线、证据、边界、未知五项作答，记录得分和关键误解。
- [ ] 存在关键误解时完成修订及一次复述复查；不能以页面渲染成功代替可理解性验收。

## 不在本任务范围
不强称系统综述完整，不将关键词聚类直接当成科研主题已确认，不更改 54 条任务的中性分析。

## 受阻时怎么处理
卡片不足以支撑某一论点时删去确定说法或标缺证据，回链 T03；不凭模型常识补证据。

## 如何提交与验收
认领后填写一位整理同学、一位同伴检查同学及预计交付日。交付候选文件或 PR 链接、基准版本和逐项证据；检查者写明结果。涉及科研取舍的事项由导师确认。仅创建文件或合并文档 PR 不关闭本 Issue。

关联旧需求：[#8](https://github.com/iHeadWater/mylibrary/issues/8)、[#6](https://github.com/iHeadWater/mylibrary/issues/6)、[#9](https://github.com/iHeadWater/mylibrary/issues/9) 旧单保留为能力方向；本单只验收当前小样本闭环的一个交付，不代表旧单的全部范围完成。

需求依据：[产品文档](../科研知识平台_产品文档.md)、[里程碑计划](../里程碑计划.md)、[验收清单](../验收清单.md)、[仓库兼容说明](../仓库兼容说明.md)。
