# [T03] 校准文献卡模板并交付可追溯的样本卡

里程碑：M1 ｜ 认领角色：初读整理同学；同伴检查同学；导师评议可用性 ｜ 建议工作量：约 1—2 天

状态：待认领。GitHub Assignee、实际日期、验收结果以对应 Issue 为准；本文为创建时的任务定义。

## 为什么做
主题综合需要问题、证据和适用条件，只有摘要和标签不能支撑后续判断。

## 输入与前置依赖
确认后的样本清单、仓库八段分析卡结构、产品文档第 3.1 节。

前置任务：[T01](T01.md)、[T02](T02.md)

## 做什么
先做一篇研究论文和一种其他论文类型的两张校准卡，评议通过后再覆盖已批准演示集。保留现有八段骨架，在段内补足原文定位、适用条件、作者解释与本方判断；补读增量进入同一卡片。

## 交付物
- 候选模板和字段说明，附与仓库现行八段结构的映射。
- 样本卡及逐篇检查记录；内容位置由 T01 确定，本 Issue 仅保存链接。
- 记录每篇处理、人工修正的用时和主要返工原因。

## 完成标准
- [ ] 每张卡有题录、所属 Zotero 库与 Key、实际阅读范围，以及可定位的来源。
- [ ] 研究问题、方法与数据、关键结果、局限及与当前主题的关系均有实质内容。
- [ ] 每张卡至少核查 2 项决定性表述的原文位置；原文不支持的表述删除或标为待核实。
- [ ] 作者结论、本方解释和未知分开；不同条件的结果不直接写成冲突。
- [ ] 两张校准卡的结构和证据质量获记录性评议后才扩到其余已批准样本。
- [ ] 同一来源未产生第二份正式卡；修订现有生产模板需另经维护流程。

## 不在本任务范围
不为补齐字段发明结果，不自动批量创建精读编号，不改全库模板。

## 受阻时怎么处理
关键图表未读到时记录缺口并定位最小补充材料；无法补足则把卡退回待核实。

## 如何提交与验收
认领后填写一位整理同学、一位同伴检查同学及预计交付日。交付候选文件或 PR 链接、基准版本和逐项证据；检查者写明结果。涉及科研取舍的事项由导师确认。仅创建文件或合并文档 PR 不关闭本 Issue。

关联旧需求：[#7](https://github.com/iHeadWater/mylibrary/issues/7)、[#6](https://github.com/iHeadWater/mylibrary/issues/6) 旧单保留为能力方向；本单只验收当前小样本闭环的一个交付，不代表旧单的全部范围完成。

需求依据：[产品文档](../科研知识平台_产品文档.md)、[里程碑计划](../里程碑计划.md)、[验收清单](../验收清单.md)、[仓库兼容说明](../仓库兼容说明.md)。
