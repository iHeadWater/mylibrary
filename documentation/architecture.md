# 当前架构

## 目标链路

```text
团队成员的私人 Zotero 账号
        ↓
指定的 Zotero 共享群组库
        ↓
指定制卡机检测父条目和 PDF
        ↓
本地运行状态与任务处理
        ↓
共享证据包、关键事件和进度摘要
        ↓
GitHub 私有仓库
```

## 数据归属

| 内容 | 权威来源 | 是否进入 Git |
|---|---|---|
| 论文元数据和 PDF | Zotero 共享库 | PDF 不进入；必要元数据写入证据包清单 |
| 证据包 | GitHub 仓库 | 是 |
| 候选与正式主题 | GitHub 仓库 | 是 |
| 关键贡献事件 | GitHub 仓库 | 是 |
| 运行游标、队列、锁、原始日志 | 指定制卡机 `.runtime/` | 否 |
| 密钥和令牌 | 制卡机本地密钥环境 | 否 |

## 已确认规则

- 取消 `students/` 目录，不按个人保存证据卡。
- 一篇论文只有一个团队共享证据包。
- Zotero 父条目 Key 是指定群组库内的内部唯一标识。
- 论文新增者、PDF 补充者和系统制卡者分别记录。
- 只从监控系统启用之日起记录贡献，不追溯历史操作。
- 监控用于掌握进度和发现阻塞，不用于排名或绩效评价。
- 新电脑可依靠 GitHub、Zotero 和重新提供的密钥恢复自动化流程。
- 可复现要求针对流程和已有结果的恢复，不要求 AI 重新生成的文字逐字相同。

## 恢复原则

- Zotero 和 GitHub 是可恢复数据源，本地 .runtime/ 只是可丢弃的派生状态。
- 恢复时先执行全量对账，再进入增量检测。
- 证据包以 Zotero 父条目 Key 定位，以 PDF 附件 Key 和文件哈希判断是否需要更新。
- 恢复扫描必须幂等：重复执行不会新建第二个证据包或重复写入相同事件。
- 调度和环境安装必须由仓库中的脚本重建，不依赖只存在于旧电脑上的手工配置。
- 所有团队级可调整路径和固定参数由 `config/config.json` 集中提供；运行状态、证据事实和密钥按各自边界保存。

## 当前非目标

- 详细证据卡模板；
- 候选主题自动生成与正式主题确认；
- 科研 idea 生成；
- 微信、邮件等外部通知；
- 对 Zotero 中每次细微编辑进行完整审计。

## 待确认

- 制卡机的在线与补跑策略；
- Zotero 检测使用本地接口、云端接口或两者结合；
- 自动化任务状态机和失败重试规则；
- 证据卡模板与主题模板的正式字段。
