# 换机恢复

## 目标

旧制卡机完全不可用时，新电脑仍能依靠以下三类输入恢复自动化：

1. GitHub 私有仓库；
2. Zotero 共享群组库及已同步的 PDF；
3. 从独立密钥存储重新提供的凭据。

## 目标恢复流程

1. 在新电脑克隆仓库；
2. 安装 Zotero，登录有权访问目标群组库的私人账号并完成文件同步；
3. 运行仓库中的安装脚本，安装锁定版本的程序依赖；
4. 检查或填写唯一总配置，并从密钥存储注入凭据；
5. 运行恢复命令，扫描 Zotero 全部父条目和 PDF；
6. 使用父条目 Key、附件 Key、PDF 哈希与现有证据包进行全量对账；
7. 重建 .runtime/ 中的游标、待处理任务和锁；
8. 受控执行一次检测与处理；
9. 恢复自动调度。

## 恢复时不得发生

- 为同一 Zotero 父条目创建第二个证据包；
- 将历史文献误记为恢复当天的新贡献；
- 因本地日志或游标丢失而跳过尚未制卡的论文；
- 把密钥、PDF 或原始日志提交到 Git；
- 自动覆盖无法解释的人工修改。

## 验收标准

在一台没有旧制卡机本地文件的干净电脑上，仅使用 GitHub、Zotero 和重新提供的凭据：

- 能安装并启动自动化；
- 能重建本地运行状态；
- 能识别已有、待处理和发生变化的论文；
- 重复运行对账不会产生重复证据包或重复事件；
- 能继续处理恢复后新增或补充 PDF 的论文；
- 能重新建立自动运行计划。

不要求同一篇论文重新调用 AI 后生成逐字一致的文本，但必须记录并可追溯所使用的提示词、结构和模型配置版本。
