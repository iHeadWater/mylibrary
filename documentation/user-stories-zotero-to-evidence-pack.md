# 用户故事：Zotero 到证据包自动化

本清单把 PRD 拆成可独立开发和验收的小任务。只有真正生成卡片的 US-07B2 依赖正式证据卡模板。US-01 至 US-07B1 已完成代码、自动化测试和相应真实正向验收；US-07B2 至 US-14 尚未实现。

## 实施顺序

    US-01 → US-02 → US-03 → US-04 → US-05 → US-06 → US-07A → US-07B1
                                      ↓
                                    US-09
    US-07B2 → US-08 → US-10 → US-11 → US-12 → US-14
                                ↓
                              US-13

US-07A 只确认制卡运行环境。US-07B1 再用固定、无论文内容的探针验证 Python 能否非交互调用模型，但不接模板、不读 PDF、不写卡。US-07B2 才负责真实生成：当前调用方式已确认为 Codex CLI 使用订阅账号；证据卡模板将由其他协作者按论文类型提供多个 Markdown 文件。仍需确认论文类型的判断和模板路由规则，收到模板后才能完成内容质量验收。US-13 已确认需要，但不是主链最先实现的内容。

## US-01：无人值守读取目标 Zotero 共享库

**状态：**已完成。目标群组 qinjiajun（6618088）已通过真实预检。

**描述：**作为自动化维护者，我希望后台命令能够在没有 Codex 对话窗口的情况下检查 Zotero 和目标共享库，以便后续任务有稳定入口。

**验收标准：**

1. 命令可以从终端非交互运行，不需要人工点击；
2. 目标 Zotero 群组 ID、可调整路径和固定运行参数来自单一非敏感总配置；
3. 能区分 Zotero 未运行、本地接口不可用、共享库不存在和权限不足；
4. 检查过程不修改 Zotero 和 GitHub；
5. 返回机器可读取的成功或失败结果。
6. 从仓库以外的工作目录执行时，路径仍相对于总配置所声明的项目根目录解析。

## US-02：建立基线并检测文献变化

**状态：**已完成。空库基线、一篇真实文献及 PDF 的新增检测、父子关联和重复扫描均已通过；后补、替换和移除场景目前由自动化测试覆盖。

**描述：**作为系统，我希望识别共享库中新出现的父条目和已有条目中新出现或替换的附件，以便只处理真实变化。

**验收标准：**

1. 能列出父条目 Key 及其 PDF 附件 Key；
2. 首次启用时建立基线，不把全部历史论文记为当天贡献；
3. 后续扫描能区分新增父条目、补充 PDF 和替换 PDF；
4. 重复扫描同一状态不会再次产生相同变化；
5. 本地基线丢失时能够转入全量对账而不是盲目重放。
6. 快照路径和扫描分页参数来自总配置，源码和命令默认值不得另行写死路径。

## US-03：PDF 全文门禁

**状态：**独立门禁已实现；真实文本 PDF 已通过。缺 PDF、未同步、未索引、多 PDF、损坏文件和疑似扫描件已有自动化测试；自动离开等待状态将在 US-04 接入任务重试后完成。

**描述：**作为导师，我希望系统只有取得可读取的 PDF 全文后才进入制卡，以免把摘要或残缺内容伪装成证据。

**验收标准：**

1. 无 PDF 的父条目进入等待 PDF 状态；
2. PDF 无法打开、为空或无法提取有效内容时进入明确阻塞状态；
3. PDF 后续补齐后能够自动离开等待状态；
4. 第一版不自动 OCR，扫描件必须被识别为当前不可处理；
5. 多个 PDF 附件无法安全判断主文时不得静默任选。

## US-04：单篇任务与幂等状态机

**状态：**已完成。任务清单、输入指纹、状态历史、原子写入、进程锁、领取租约、过期重试和完成保护已实现并通过自动化测试；一篇真实文献已验证首次任务创建和第二次同步零变更。当前正常终点为 `READY_FOR_EXTRACTION`，不伪造后续 `COMPLETED`。并发领取、租约过期和损坏任务清单等异常路径尚未进行真实故障演练。

**描述：**作为自动化维护者，我希望每篇论文有唯一任务和明确状态，以便崩溃、重试和重复运行都不会造成重复结果。

**验收标准：**

1. 任务唯一性由目标群组、父条目 Key、附件 Key 和 PDF 哈希共同约束；
2. 同一时刻只允许一个进程处理同一篇论文；
3. 程序异常终止后能够识别未完成任务并安全重试；
4. 已成功处理且 PDF 未变化的论文不会重新生成；
5. 每次状态变化都有时间和原因，但原始运行日志不进入 Git。

## US-05：创建证据包骨架

**状态：**已完成。代码和自动化测试通过；一篇真实 `READY_FOR_EXTRACTION` 任务已验证首次创建证据包、来源追溯、最小占位卡和第二次同步零新增。正式证据卡字段不属于 US-05，异常路径尚未进行真实故障演练。

**描述：**作为团队成员，我希望一篇论文只形成一个共享证据包，以便所有人引用同一份知识资产。

**验收标准：**

1. 目录采用 EV-父条目Key-简短标题；
2. 每个证据包包含 manifest.json 和 card.md；
3. manifest 至少记录证据 ID、父条目 Key、附件 Key、PDF SHA-256、创建时间和更新时间；
4. 正式模板确认前，card.md 只包含标题“待生成证据卡”和状态 `PLACEHOLDER`，不提前加入任何证据字段；
5. 重复运行不会创建第二个目录，也不会覆盖已经不再是占位状态的 card.md；
6. manifest.json 和 card.md 均成功落盘后才算证据包骨架创建成功；不完整目录不得被当作成功结果。

## US-06：验证并交付 Zotero 原始 PDF

**状态：**已完成。代码和 6 个自动化测试通过；真实论文 `CEXH4PQA` 已验证原始 PDF 路径、附件 Key、任务 ID、SHA-256 和证据包关联一致，并经只读检查确认没有复制 PDF、改写占位卡或改变任务状态。US-06 不导出或持久保存全文文本，也不调用 AI。

**描述：**作为证据卡生成器，我希望每次取得并验证一篇论文在 Zotero 中保存的原始 PDF，以便后续制卡 Agent 接收完整文件，而不是只收到标题、摘要或检索片段。

**验收标准：**

1. 每个任务只向后续处理器交付一篇由群组 ID、父条目 Key 和附件 Key 唯一定位的 Zotero 原始 PDF；
2. 交付前重新计算 PDF SHA-256，并与任务及 manifest.json 中的输入指纹一致；
3. 后续制卡 Agent 接收原始 PDF 文件本身或等价的完整字节流，不得只接收标题、摘要、Zotero 全文索引或局部文本；
4. 默认不复制 PDF，不生成必须长期保存的全文文本或解析缓存，PDF 继续由 Zotero 管理；
5. PDF 无法访问、文件版本不一致或交付失败时不得调用 AI，并记录明确原因；
6. US-06 只验收“完整 PDF 已被正确交付”，AI 是否充分利用跨页内容由 US-07B2 的专门测试验收。

## US-07A：Codex CLI 与 ChatGPT 账号登录预检

**状态：**已完成。代码和自动化测试通过；真实制卡机已确认 Codex CLI 0.149.1 可运行，并明确报告为 ChatGPT 账号登录。该结果不依赖正式证据卡模板，也不能证明订阅档位或剩余额度。

**描述：**作为自动化维护者，我希望用一个只读命令确认配置的 Codex CLI 可执行且使用 ChatGPT 账号登录，以便在接入真实制卡前发现安装或认证阻塞。

**验收标准：**

1. `card_generator` 的适配器、可执行程序、认证方式和预检超时全部来自总配置，未知适配器或认证方式立即报配置错误；
2. `generator-preflight` 只运行 Codex CLI 版本检查和登录状态检查，不访问 Zotero、PDF、模板、任务或证据包，也不运行 `codex exec`；
3. 只有明确识别为 ChatGPT 账号登录时才通过；API Key 登录、未登录和无法确认登录类型都不得误报成功；
4. 能区分 CLI 不存在、CLI 无法运行、检查超时、未登录、认证方式不匹配和认证方式未知，并返回机器可读取的错误码；
5. 输出不得回显登录状态命令的原始内容或任何凭据；成功返回 CLI 版本、实际可执行程序路径和配置认证方式。

## US-07B1：无论文的最小模型调用探针

**状态：**已完成。真实制卡机已通过 Python 使用 ChatGPT 账号调用 `gpt-5.6-sol / low`，固定响应、隔离工作区、只读沙箱、临时会话和无工具活动均验收通过。探针输入 token 为 16,324，因此不得作为每日健康检查。

**描述：**作为自动化维护者，我希望 Python 在受限环境中调用一次 Codex 并取得固定机器可读响应，以便在接入论文和模板前确认订阅调用链、错误识别和输出协议真实可用。

**验收标准：**

1. 只有 US-07A 预检通过后才执行 `codex exec`；预检失败时不得调用模型；
2. 调用使用固定且版本化的无论文提示，只允许返回 `HYDRO_GENERATOR_OK`；模型在系统临时创建的空目录中运行，不以项目仓库为工作目录，不得接触 PDF、模板、任务或证据包；
3. 强制使用 `read-only` 沙箱、`--ephemeral`、`--ignore-user-config`、`--ignore-rules`、`--skip-git-repo-check` 和 JSONL 输出；临时空目录在调用结束后删除，不写会话文件、模型输出文件或仓库内容；
4. 模型、推理强度和调用超时来自总配置；模型或推理强度留空时使用模型默认，显式填写时分别通过 `--model` 和 `--config model_reasoning_effort="..."` 使用该值；
5. 能识别调用超时、认证失效、速率限制、用量不足、模型不可用、推理强度不兼容、JSONL 协议异常、非预期输出和工具活动；失败不重试、不写卡，也不回显原始错误内容。

## US-07B2：接入版本化 AI 证据卡生成器

**状态：**已确认未来由 Python 后台程序非交互调用 Codex CLI，并使用制卡机上已登录的 ChatGPT 订阅账号；不依赖 Codex 对话窗口，也不使用单独计费的模型 API。真实模型调用尚未实现，正式证据卡模板仍待外部协作者交付。

**描述：**作为团队，我希望后台程序能通过可替换的制卡接口调用已登录的 Codex CLI，并记录所用规则，以便当前用订阅账号无人值守制卡，未来更换模型时不重写整条流程。

**验收标准：**

1. Python 程序通过非交互 Codex CLI 发起制卡，不需要打开 Codex 对话窗口或由人工发送消息，并且必须先通过 US-07A 和 US-07B1；
2. 一次调用只处理一篇论文，并把 US-06 校验后的完整 PDF 交给 Codex；至少用一篇需要跨页取证的样本验证模型不是只依据标题、摘要或首页作答；
3. 只有证据包中的 card.md 仍为 `PLACEHOLDER` 且输入指纹与 manifest.json 一致时，系统才调用 AI；
4. card.md 已包含粗证据卡或其他非占位内容时直接跳过，不调用 AI，也不改写已有卡片；
5. 外部 Markdown 模板、提示词、输出结构、Codex CLI 版本和模型配置都有版本标识；每篇论文必须选择唯一模板，未知或冲突类型不得静默套用默认模板；输出按所选模板对应的结构校验；Codex 登录凭据只存在本机凭据存储；
6. 能区分 CLI 未安装、登录失效、订阅额度或限流、超时和模型输出无效；失败时保持占位卡并进入明确阻塞或安全重试，不重复写卡。正式证据卡模板未确认前，不得宣告科研质量验收通过。

## US-08：校验并原子更新证据包

**描述：**作为导师，我希望只有满足结构要求的输出才进入共享仓库，以免半成品污染知识库。

**验收标准：**

1. 写入前校验 manifest 和卡片结构；
2. 校验失败时保留原有有效证据包；
3. 写入过程被中断时不留下看似完成的半个证据包；
4. 自动写入只允许把 `PLACEHOLDER` 占位卡替换为第一次生成的粗证据卡；已有非占位卡不得自动覆盖；
5. PDF 输入发生变化时停止自动制卡并进入待处理状态，不用新输入覆盖旧卡；
6. 首次粗卡成功写入并记录来源 PDF、提示词和模型配置版本后，才把任务标记为完成。

## US-09：记录关键贡献与系统事件

**描述：**作为导师，我希望看到谁新增论文、谁补充 PDF，以及系统是否完成制卡，以便掌握进度和发现阻塞。

**验收标准：**

1. 新增父条目和补充 PDF 分别记录实际 Zotero 用户；
2. 系统制卡事件统一记录为 SYS-CARD-01；
3. 无法识别用户时记录未知，不猜测归属；
4. 系统启用前的历史操作不追溯为个人贡献；
5. 事件只用于流程追踪，不生成排名或绩效分数。

## US-10：安全同步 GitHub

**描述：**作为团队成员，我希望有效证据包自动进入私有 GitHub 仓库，以便共享和保留版本历史。

**验收标准：**

1. 只有通过校验的证据包和允许共享的事件可以提交；
2. PDF、密钥、.runtime 和原始日志不得进入提交；
3. 推送前先同步远端变化，并避免覆盖无法解释的修改；
4. 推送失败时保留待同步状态，不能重新生成第二份证据包；
5. 提交信息能关联父条目 Key 和自动化运行。

## US-11：每日无人值守运行与补跑

**描述：**作为导师，我希望系统每天自行运行，即使曾关机或 Zotero 暂时不可用，也能在恢复后补跑。

**验收标准：**

1. 不打开 Codex 窗口也能按计划运行；
2. 同一时刻只允许一个计划任务实例执行；
3. 运行前检查 Zotero、共享库同步、网络和 Git 状态；
4. 错过计划时间后能够在机器恢复时补跑；
5. 短暂失败可重试，持续失败进入阻塞而不是无限循环。

## US-12：新电脑安装与全量恢复

**描述：**作为自动化维护者，我希望旧电脑完全损坏后仍能在新电脑恢复流程，以免系统依赖个人机器。

**验收标准：**

1. 从 GitHub 克隆后可以按文档或脚本安装锁定依赖；
2. 登录 Zotero、同步共享库并重新提供密钥后可以执行恢复；
3. 恢复过程能够重建 .runtime；
4. 全量对账不会重复生成证据包或历史贡献事件；
5. 自动调度能够被重新建立并通过一次自检。

## US-13：生成每日进度摘要

**描述：**作为导师，我希望每天看到新增、完成和阻塞摘要，以便快速了解流程状态。

**验收标准：**

1. 摘要至少包含新增、完成、未解决阻塞和系统运行状态；
2. 持续未解决的阻塞不会因跨天而消失；
3. 无变化日仍能说明检测是否正常运行；
4. 摘要显示相关贡献者但不做排名；
5. 日报详细字段和通知方式后续再定。

## US-14：三篇样本端到端验收

**描述：**作为团队，我希望用小样本证明自动化闭环真实可用，再决定是否处理 50 多篇灾害链文献。

**验收标准：**

1. 使用 2 篇正常 PDF 和 1 个缺失或不可读 PDF；
2. 正常样本各生成一个且只有一个证据包；
3. 负面样本进入明确阻塞，不生成正式卡；
4. 连续运行两次，结果不重复；
5. 删除本地运行状态后恢复，结果仍一致；
6. 保留运行证据，能够说明每项验收是否通过。
