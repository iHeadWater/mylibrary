# 自动化边界

## 自动化所有者

- 人工参与者：使用私人 Zotero 账号的老师和学生。
- 自动化执行者：`SYS-CARD-01`，即运行在唯一指定制卡机上的 Python 后台程序；当前已负责检测、门禁、任务、证据包骨架、PDF 交付、Codex CLI 运行环境预检和无论文最小调用探针，US-07B2 再接入非交互 Codex CLI 正式制卡。
- Git 写入权：当前只授予指定制卡机；成员通过 Zotero 共享库提供输入。

## 允许读取

- 指定 Zotero 共享群组库中的父条目、附件和必要身份信息；
- Zotero 已同步到制卡机的 PDF 全文；
- 仓库中已有的证据包与非敏感配置。

## 允许写入

- `evidence-packs/` 中的证据包；
- `activity/` 中的关键事件；
- 后续启用的 `reports/` 摘要；
- 制卡机本地 `.runtime/` 状态。

## 禁止行为

- 未取得可读取的 PDF 全文时生成正式证据卡；
- 对已有非占位证据卡重复调用 AI 或自动覆盖；
- 把 PDF 原文、密钥或原始运行日志提交到 Git；
- 自动把候选主题升级为正式主题；
- 将活动数量解释为学生绩效。

## 当前实现与边界

当前已经实现 Zotero 群组预检、扫描基线、父条目与 PDF 附件变化检测、单篇论文的只读 PDF 全文门禁、本地任务状态机、证据包骨架、经过哈希复核的 Zotero 原始 PDF 只读交付、Codex CLI/ChatGPT 登录方式预检，以及固定无论文内容的最小模型调用探针。US-06、US-07A 和 US-07B1 已通过真实正向验收。尚未实现 AI 正式制卡、调度和 Git 自动同步。

US-07A 已在 `automation/src/hydro_platform/card_generators/` 建立首个真实适配边界，并注册 `codex_cli`。预检只运行版本和登录状态检查，不运行模型，不读取论文，也不把登录命令原始输出写入结果。它使用制卡机上已登录的 ChatGPT 账号，不使用项目配置中的 API Key，也不依赖 Codex 对话窗口。

US-07B1 在预检后，在系统临时创建的空目录中使用 `codex exec --json --ephemeral --sandbox read-only --skip-git-repo-check` 执行固定探针，不把项目仓库设为工作目录。程序从总配置读取模型和推理强度，分别通过 `--model` 和显式 `--config model_reasoning_effort="..."` 覆盖 Codex 默认；两者为 `null` 时保留模型默认值。程序额外忽略用户配置和规则，拒绝命令执行、文件修改、MCP 调用或联网搜索事件；只接受固定响应，不保存原始 CLI 输出，并在结束后删除临时目录。真实验收已用 `gpt-5.6-sol / low` 成功完成，但固定探针仍消耗 16,324 个输入 token；它不能进入每日调度，只能用于安装或配置变化后的受控验收。

US-07B2 才会接入真实制卡。接入前仍必须取得外部 Markdown 模板，并确认论文类型与唯一模板路由、正式模型、推理强度、订阅用量限制，以及论文 PDF 的传输、训练使用和保留政策。Codex 登录凭据只能保存在本机凭据存储中，不得写入仓库、日志或证据包。

无人值守运行前必须执行 `generator-preflight`。US-07B1 可以识别一次真实调用中的额度或限流失败，但不自动重试，也不能保证未来调用始终可用。US-07B2 需要把这些失败映射为明确任务阻塞，不得无限重试或把占位卡当作正式结果。未来如接入独立 API，应作为新的可替换适配器，并另行定义凭据、计费和数据边界。

## 可复现要求

- 源代码、提示词、结构定义、非敏感配置和依赖锁定文件必须进入 Git。
- 每次生成都要记录使用的流程版本；不要求大模型输出逐字确定。
- 自动化不能把本地游标当作唯一事实来源。
- 本地状态丢失后，必须通过全量对账安全恢复，之后才能继续增量处理。
- 安装脚本必须能够重建 Windows 调度任务，避免只有旧电脑知道如何运行。
