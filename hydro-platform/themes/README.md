# 统一主题池

主要阅读入口：[index.md](index.md)。它链接当前主题及演变历史；进入主题后主要看精读回填的 revised.md，不必从文件夹猜最新版。

## 存储分工

| 位置 | 作用 |
|---|---|
| _registry.json | 稳定编号、当前版本、历史版本、前身/后继、输入处理指纹 |
| candidates/TH-编号/versions/CHANGE-编号/ | 新主题及更新版本；initial.md 初版、revised.md 回填结果、plan/manifest/结果 JSON |
| changes/CHANGE-编号/ | 一次处理的输入、规划、结果发布记录；不是独立知识池或 Git commit |
| changes/IMPORT-编号/ | 已有成果接入统一池的记录 |
| candidates/BATCH-*/ | 已有旧成果原位置，继续被统一池引用，不搬动或重做 |
| confirmed/ | 正式主题预留区；专用人工确认入口尚未实现 |

## 演化规则

全部有效粗卡、已有修订主题及适用历史精读共同参与规划。关联依据研究问题、机制与证据，不由程序按关键词强制合并。

- 补充/修正：沿用主题编号，增加版本。
- 合并/拆分：创建新编号，旧主题保留为历史，前后双向追溯。
- 精读适用时复用；问题/重点改变且旧精读不足时，再读原始 PDF。
- 定向精读始终存于对应证据包 readings/，主题只引用，不改主粗卡。
- 所有新版本准备完才整体发布；失败不先废弃旧主题，已完成步骤可续用。
- 正式主题不能被自动操作覆盖；更新建议另建候选，不自动晋级。
- 相同输入不调用模型，换 batch 不构成重读理由。

## 操作

项目根目录的 run-once 已接入主题；仅推进主题用：

    python automation/run.py themes-run --json

--dry-run 只读预览，--migrate-only 仅迁移已有完成成果、不调用模型。不要手改索引/注册表或移动被引用文件；冲突时程序保留文件而非覆盖。

当前已有两个迁移后的候选，均未人工转正式。合并/拆分的程序保护有测试，真实 AI 关联判断质量仍待实测。
