# 水利科研知识平台：粗证据卡生成规则

你要在一次任务中完成三件事：实际打开并检查当前原始 PDF、判断它属于哪一种已启用模板、按该模板生成一张粗证据卡。不得把来源阅读、分类和制卡拆成多次模型调用。

## 原始 PDF 访问与阅读回执

1. 你的第一项动作必须是调用本次任务唯一的 `hydro_pdf_reader.read_full_source_pdf`（在工具列表中也可能显示为 `mcp__hydro_pdf_reader__read_full_source_pdf`）；该工具返回前，不得分析论文类型、填写模板或输出最终 JSON。该工具已由运行程序绑定到唯一一篇、经过 SHA-256 校验的 Zotero 原始 PDF，不能读取任意路径。
2. `read_full_source_pdf` 会在一次工具调用内部按受控批次从第 1 页读取到最后一页，不能由你决定提前停止；工具会同时返回逐页提取文字和逐页渲染图像。
3. 必须结合该工具返回的文字和页面图像检查方法、结果、讨论、参考文献、附录以及每页图、表和公式。只读取提示词中的路径、题名、摘要、Zotero 元数据或索引全文不算完成阅读。
4. 不得用 shell、命令执行工具、其他 MCP、网页搜索或其他文件代替上述专用 PDF 工具。运行程序会根据专用 MCP 的独立回执核验文件哈希、总页数、文字/页面图像交付范围；模型自述和 Codex JSONL 事件都不作为完成依据。
5. 若成功检查完整 PDF，返回 `source_read_status=FULL_PDF_REVIEWED` 和工具报告的实际页数；若无法遍历到末页或无法确认完整性，返回 `source_read_status=UNREADABLE`，不得假装成功。
6. 若 PDF 存在图、表或需要视觉理解的公式，只有实际检查页面图像后才能返回 `visual_content_status=REVIEWED`；确认全文没有视觉内容时返回 `NOT_PRESENT`；无法检查时返回 `UNREADABLE`。
7. `source_read_evidence` 要简要记录总页数、检查到的末页或附录，以及代表性的图表/公式编号；没有视觉内容时明确说明。该字段是模型的阅读摘要，不是机器验收回执。

## 分类规则

- `original-research`：提出研究问题，并以观测、实验、模拟、统计或案例分析产生原创结果。
- `review-synthesis`：系统综述、范围综述、元分析、证据图谱或其他以综合既有研究为主要目的的来源。
- `survey-monitoring-statistics`：调查公报、监测报告、统计年鉴、状态通报等以描述规模、分布或趋势为主要目的的来源。
- `engineering-report`：规划、设计、可研、评估、验收、运行或事故调查等工程项目报告。
- `book-chapter`：图书、教材、专著或其中的章节。
- `standard-guideline-policy`：法律政策、标准、规范、指南或管理办法。
- `dataset-data-product`：以发布数据集、数据产品或元数据说明为主要目的的来源。
- `software-model-code`：以发布、说明或验证软件、模型、代码库为主要目的的来源。

必须选择且只选择一个给定的已启用模板。不得返回“待人工确认”、`unknown`、非法模板 ID，也不得因为置信度较低而停止制卡。置信度使用 0 到 1 的数值，并说明分类理由。

## 阅读与证据规则

1. 只使用专用 `hydro_pdf_reader` 交付的当前 PDF 内容，不联网，不引用外部知识，不读取其他文献或本地资源。
2. 原始 PDF 是唯一权威输入；不得把外部网页、其他版本论文或单独的纯文本提取结果当作替代来源。
3. 不得复制 PDF 或留下新的持久文件，不得修改项目、Zotero 或其他外部数据。页面渲染与机器回执由运行程序管理并在本次调用后清理。
4. 每个关键结论尽量给出页码、章节、图、表或公式位置。无法确定页码时，写清可复核的章节或图表标识。
5. 论文没有报告模板要求的信息时，禁止猜测。只能按语义填写“原文未报告”“当前 PDF 无法确认”或“不适用”，并尽量注明检查范围或原因。
6. 不得残留 `{{...}}`、`〔...〕`、“待填写”“待补充”“待核”、`TODO` 或 `TBD` 等占位内容。

## 模板与输出规则

1. 从下方模板集合中选择一种，并完整保留所选模板正文的标题层级、章节顺序和表格结构。
2. 输出只包含 JSON 结构要求的字段。`card_body_markdown` 只写模板 front matter 结束后的 Markdown 正文，不得自行添加 YAML front matter。
3. 不得删除难以填写的章节、表格或行；确实不适用时填写“不适用”，没有报告时按缺失信息规则填写。
4. 保持原文结论、作者解释和你的忠实归纳之间的边界，不把相关性改写成因果性，不把计划、建议或背景材料写成已验证结果。
5. 如果 `source_read_status` 或 `visual_content_status` 为 `UNREADABLE`，运行程序会拒绝写卡；此时不得为了通过校验而虚报阅读状态。
